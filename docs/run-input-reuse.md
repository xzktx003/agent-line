# 用原始输入准备一次新运行

在运行管理中选定原工作流和运行，展开“以原输入准备新运行”，点击读取原输入。查看完整JSON，勾选覆盖确认，再点击“填入新运行表单”。页面填入当前绑定和原输入，生成新触发标识并清除此前选用的业务任务关联。之后仍须核对目标和副作用、重新选择所需业务任务，再单独点击原“启动工作流”。

这是新运行的表单准备，不是恢复、业务重试或重放原提交。原运行可能仍活动、等待或未知；此处不查询或改变其原生状态，也不将未知改成未受理。确认文字明确新运行可能再次产生业务副作用。不复制旧审批、输出、执行/激活/尝试身份、提交回执或传输触发键。新启动继续经过原角色/发布/就绪/预算/幂等边界。

新增 `GET /extension/v1/workflows/{binding_id}/runs/{run_id}/input` 使用原运行Bearer及项目范围；先复用known_run，已发布绑定必须匹配原publication快照。只读SQLite根context输入，不访问Sim或原生宿主，不登记任何提交意向。读取后重新确认绑定未变化。

响应固定为 `source: local_run_input`、readOnly=true、executionSupported=false、bindingId/projectId/workflowId/runId、inputSha256和input；no-store/nosniff。指纹基于原规范JSON值，不保证原JSON文本格式或空白复现。仅返回初次根输入，不是恢复点输入、角色加工后的指令或当前任务输出。

SQL在取正文前限制原输入64,000字节；JSON必须为对象，拒重复键、非有限值、非法Unicode和超出JavaScript安全范围的数值，避免回填后编号舍入。无记录/范围不符404，超限413，坏输入/账本无法核实503，读取期间绑定变化409。超范围旧输入仍保留，不自动转换或覆盖；应人工准备可安全表达的新输入。

前端检查来源、项目/工作流/运行身份、结果结构与规模。读取时捕获启动表单、触发键、输入和业务任务选择摘要，任何变化后都需重新读取和确认；切来源/身份清旧内容，迟到响应不能覆盖新选择。当前凭证在任何输入字符串或对象键中出现时，禁止展示和回填。原输入不写浏览器存储或URL。

本页面身份内已发起而尚未取得明确accepted/rejected回执的启动，以及正在提交的启动，会阻止此回填覆盖原触发标识。该前端记录只保护本页面的输入复用，不是新增持久提交系统；原持久防重仍由后端承担，不能通过刷新、换身份或生成新键认定旧未知任务未执行。明确回执后才可继续准备；未知则保留原触发键核对原提交。

实现修改原SimJournal、WorkflowGateway路由，前端复用模块、原运行表单和业务任务选择清理。没有新调度器、依赖或QwenPaw改动。指定gpt-6-luna负责后端及独立源码复核，根集成并做2个Python文件AST解析；未运行测试、Node、HTTP、浏览器、模型、lint/typecheck/build。部署只证明加载与数据配置保持，实际读取/预览/回填/新启动尚未验收，完整PRD和AC不提升。
