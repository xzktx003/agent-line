# 角色与工作区串行队列

复用 TaskStore、现有登记事件序号、写租约和 ExecutionWorker；不新增表、依赖、
队列进程或图调度。Sim仍唯一推进节点后继。

1. 对同一正式角色ID（即使项目标签不同），或解析后相互包含的工作区，固定串行准入。
   registered事件的持久seq决定先后，不依赖UUID字典序或墙钟。
   SQLite BEGIN IMMEDIATE内同时检查前序排队、活动角色和写租约，再持久提交意图。
2. 早登记任务暂停或版本检查阻塞时保留队位；需通过现有恢复/停止原任务处理，
   后续相关任务不悄悄越过。独立角色且不重叠工作区可以各自执行。
   未知、取消未确认、执行结束但资源/验收未释放的原租约继续阻止准入。
3. 认证任务列表与详情显示当前排队原因和固定策略，不返回其他任务ID、路径、
   项目或角色信息。读取不产生事件/模型/原生写入，不把资源可用视为执行已就绪。
4. 复用现有取消排队入口；重启从原登记事件和租约重建顺序。
   先验证逆序提交、竞争、取消/未知/重启与隔离，再接入原中文状态行并验证。

这是实施计划；真实多运行争用及所有AC-35验收未完成前不提升状态。

队列只显示本任务的资源/顺序等待诊断；暂停与角色版本阻塞分别保留在原运行控制和
submissionBlock视图。暂停头任务不会被越过。跨项目争用只显示概括等待原因，
不返回其他项目身份、任务、队位数量或内容。
