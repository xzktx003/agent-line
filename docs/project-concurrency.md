# 项目执行并发上限

项目注册项可选配置 `maxConcurrentTasks`，严格整数1–100。不配置时保持现有行为；当前正式配置未新增此值。上限由服务端从登记项目取值，写入新节点任务payload；公开节点请求不能自行指定。TaskStore登记校验并纳入既有幂等摘要，配置变化不会覆写旧任务。同一幂等键重放先复用原登记的声明（含原来未声明），再由register核对完整载荷摘要；配置变更不会单因这个新增字段破坏原请求重放。

领取任务时沿用原BEGIN IMMEDIATE事务、角色/工作区排队与租约，不新建调度器或表。同项目未完成/未释放任务声明的上限取最小值，在领取和租约写入同一事务内判断占用；多个进程不能同时读取同一空余名额后各自领取。排队任务只保留上限，不占执行名额；提交中、受理未知、取消待退出和终态未释放均保留占用，角色和工作区限制可能进一步串行化。跨项目不共享此上限。

仍活跃的旧无字段任务计入占用，也遵守同项目未完成任务的有效上限。所有声明该上限的任务结束并释放后，该冻结上限退出约束；更改配置只影响此后登记。要降低或提高项目上限，先理解旧任务保留的约束；此机制不是热更新全局开关。若存在未知状态或执行与租约关系无法确认，拒绝新领取，不当作空闲。

私有任务详情展示当前项目的上限、占用和剩余快照，不返回其他任务身份或路径。队列关注事项说明项目名额已满。它是执行阶段任务数量限制，独立验收/记忆阶段不在占用内；不是token或金额预算，也不代表Sim流程运行并发数。取消请求不等于返还名额。
