# 中文流程编辑器：静态并行与结果汇合

2026-10-23增量：[多阶段静态并行](multi-parallel.md)把编译、发布核验和能力声明允许的编辑范围扩至最多10组。下文“只一对”及浏览器结果是原单组批次的历史边界，不能作为当前多组功能已验收的证据。仍不支持循环混用、嵌套或动态分发。

本增量沿用 `/workbench/editor.html` 的节点列表、SVG 画布、节点表单和连线列表，增加「并行分发」与「结果汇合」。QwenPaw 继续负责原生 Agent、会话和记忆；页面不执行任务、不创建原生角色、不新增记忆引擎。编译、发布与实际调度仍由既有 authoring 后端及 Sim 承担。

## 搭建方式

1. 在现有「添加节点」入口创建并行分发、两个或更多 Agent 任务和结果汇合。
2. 为每个 Agent 明确选择既有角色、任务输入与原生记忆策略，并自行开启「允许已确认失败结果进入后续分支」。页面不会自动改变策略。
3. 在并行分发表单多选 2–20 个不同 Agent、选择配对汇合、设置不小于分支数且不超过 20 的整数并发上限。
4. 在汇合表单反向选择该并行分发，并选择「全部分支成功」「允许部分分支失败」或「指定分支必须成功」。指定策略必须选择非空的配对分支子集；其他策略保存空的 `requiredBranches`。
5. 通过现有连线操作，准确连接「并行分发 → 每个 Agent → 同一个汇合」。每个分支 Agent 只允许一个入口与出口；分发节点支持多条默认出口。汇合后连接后续节点。
6. 应用各节点表单、保存草稿，再单独发布。编辑器不会运行流程。

已配对的汇合结果可以作为下游 Agent 输入（`inputFrom.field = output`）、条件规则 `source` 或结束节点 `resultFrom`。条件字段沿用 `result.verificationStatus` / `result.output.xxx`。来源必须是到达消费者的所有路径必经节点；分支 Agent 的输出不能越过汇合直接用作后续节点输入。

本次只支持一对静态分发与汇合；暂不支持与有限循环混用，不提供嵌套并行、动态分支或分支内子图配置。用户删除的分支、配对节点及结果来源会保留原 ID 并明确提示失效，需人工修正，不静默重绑。新增图配置字段、未知策略或未知节点保持只读保护，不能覆盖；原图不会被转换或删减。

## 保存与权限保护

保留既有 `dirty` / `formDirty` 语义：未应用的节点表单禁止保存与发布；保存回执只在本地快照仍一致时更新 digest。角色绑定仍由服务端项目 roles API 核验，读取失败或绑定失效时不能保存含 Agent 的图。发布使用当前已读回的 digest，独立于保存。

提交结果未知时固定原操作 ID，仅查询原操作，不自动重发；注销清空凭证、草稿、分支选择和配对信息，并拒绝迟到响应。凭证不写 URL、localStorage 或 sessionStorage。

## 本次验证

运行环境复用已有 Playwright / Chromium 与临时库，不安装依赖、不启动页面服务器、不调用真实 API 或模型：

```bash
node --check frontend/editor.js
FONTCONFIG_FILE=/tmp/agentteams-browser-fonts/fonts.conf LD_LIBRARY_PATH=/tmp/kanban-browser-libs/usr/lib/x86_64-linux-gnu .venv/bin/python probes/sim/editor_parallel_offline.py
```

浏览器探针拦截全部请求；每个允许保存的 payload 先经过真实 `compile_document(document, "offline-workflow")` 编译校验，才返回模拟回执，覆盖全部三种策略。验证三种策略的编辑、保存 payload、读回和发布，必需分支子集、分支数量、并发上限、精确连线及分发多出口，汇合后 Agent / 条件 / 结束来源、分支旁路不提供、源删除、循环混用、未知配置只读、未知保存只查询、迟到读回隔离和注销清空。桌面 1440 与手机 390 像素均未发生文档级横向溢出；画布内部保留既有横向滚动。

结果、桌面/手机截图与视觉验收保存在 `.omx/state/editor-static-parallel/`。这是离线 UI 契约证据；不证明正式部署已启用、真实 Sim 并行执行或真实 QwenPaw/Codex 端到端通过。后端与运行验收由主线独立验证。
