# 工作流目录搜索与运行信息

编辑器的项目流程目录支持按名称、描述搜索，显示 Sim 返回的运行次数和最近运行时间。搜索提交后从第一页开始；翻页与刷新沿用已提交条件，清除、切项目或退出清空条件。字段缺失显示未知或尚无记录，不从本地节点任务推算原生运行记录。

服务端只扫描本项目已受理创建记录，逐项读取 Sim 原始详情，再按去除首尾空白后的搜索词进行不区分大小写匹配。每次最多扫描指定 limit 条（1–100），nextCursor 是最后扫描的创建记录，不是最后命中的流程。过滤后本页可能为空但仍可继续下一页；页面明确区分这种情况与已经扫描结束。此方式保留项目所有权边界，不搜索共享工作区的其他项目。

接口为 GET /extension/v1/authoring/projects/{project}/workflows，增加 search 参数（最长255字符）和 search、scannedCount 回执；原 after、limit 继续生效。前端核对回执搜索词，旧后端未支持搜索时显示读取失败，避免把未过滤结果展示为搜索成功。全部为只读，不写创建日志或启动执行。迟到响应在退出或切项目后失效，凭据与搜索不写浏览器存储。

## 当前发布版本

目录额外读取官方 GET /api/v2/workflows/{id}/deployment，展示 activeDeployment.version 和 needsRedeployment。不使用最新发布日志推断当前版本，因此原生回滚和撤下发布都以实时部署状态为准。响应须与工作流身份匹配；发布状态与 activeDeployment 矛盾、版本为布尔值或无效整数等均拒绝。读取失败保留条目并显示“发布状态待核对”，不把未知标成草稿。此请求经过原工作区身份检查，不新增权限或写接口。

新增5项检查通过；相关回归运行71项通过（含当时测试导入导致的重复 transport 用例，随后已去掉重复发现，5项新检查再次通过）。两种宽度浏览器补验当前版本、草稿未发布修改、未知状态通过。真实现有3个流程分别读到v2、v1、无发布版本，共6次GET、3次deployment读取，未发变更请求，原创建/运行日志摘要保持。证据 native-deployment-report.json，复验命令 `.venv/bin/python -m probes.sim.directory_deployment_read`。这是当前客户端对真实接口的验证，主后端仍待统一重载。

归档分析发现 Sim 的官方软归档还会关联归档触发器等资源，且 active workflow history 的读取可能被关闭；在验证历史可追溯性前，未向正式流程发送归档请求。不能以本地隐藏列表代替原生归档或完整验收。
