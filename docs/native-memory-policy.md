# QwenPaw 主程序与原生记忆约束

用户最新确认：QwenPaw 是主要程序，保留官方原生记忆系统，新增功能尽量通过插件或外层包装实现，以便持续跟随官方仓库升级。本约束优先于此前为解决删除边界提出的自定义记忆提供器设计；当前 PRD v2.1 的第 1.3 节已明确此边界。

## 最新实施收缩：优先拼接原仓库能力

从头审计后的具体处理以[保留、替换与删除清单](reuse-first-reassessment-20261023.md)为准。主要收缩对象是独立画布及其图格式转换依赖，不能只把“薄适配”作为表述而继续扩张同一实现。

用户再次明确要求减少自写代码、降低工作量与故障风险。后续以原有QwenPaw、Sim、Codex和现有插件接口完成需求；这一要求约束实现方式，不将尚未完成的需求或验收改成已完成。

- 优先调用官方API、工具、配置与现有页面；需要复用源码时保留许可证和来源，将少量适配集中在本仓库，不复制整套上游模块形成长期维护分叉。
- QwenPaw原生角色、会话与ReMe保持唯一权威；Sim保持流程保存、发布、条件、等待和调度的唯一权威；Codex保持实际编码入口。扩展不平行维护这些能力。
- 暂停独立中文编辑器及管理页面的可选功能扩张。先核对上游已有页面能否承接具体交互，缺少中文时优先做必要中文入口和说明；不把英文原画布直接当作完整中文交付。
- 必要接线仍保留：项目/角色绑定、认证、跨系统任务身份、幂等与未知回执核对、审批映射和执行证据。删除这些保护不等于减轻架构；也不为保护继续增建通用平台。
- 遇到官方能力缺口，先说明限制和最小可用路径，避免再实现一套记忆、升级控制器或调度系统。没有运行证据时保持未验证。

### 后续删减顺序

本节为修改业务代码前的清理计划，本轮不删除运行模块或迁移数据：先将具体重复交互对应到官方接口/页面；再核对调用方、权限、中文覆盖、既有任务与恢复路径；只有替代路径明确时才删除对应自写代码。优先删除确定无调用的可选重复实现，不新增框架或依赖，不重写已稳定的核心接线。用户现已恢复测试，替换前优先复用必要回归验证原行为；缺少行为证据的较大替换暂不执行，不以源码审查声称安全迁移完成。

固定职责如下；QwenPaw 始终是主程序和用户入口。

| 组件 | 职责 |
| --- | --- |
| QwenPaw | 官方 Agent 创建与复用、会话、原生 ReMe 记忆存储与检索 |
| 一个 QwenPaw 官方机制插件 | 接入工作流入口和必要工具，不维护另一套 Agent 或记忆 |
| Sim | 保存、发布和执行流程，处理节点间 if/else 等分支 |
| 现有适配服务 | 连接节点与 Agent、委派 Codex、保存任务关联与执行回执；不调度另一套流程 |
| Codex | 实际编码，将结果和证据返回原 QwenPaw Agent |

优先做好“选择已有 Agent → 配置流程和条件 → 调用 Codex → 结果回到原角色”。长期记忆正文和检索继续由 QwenPaw 管理，扩展账本只用于接口关联、回执和证据。SwarmClaw、DeepSeek Harness 的功能按需参考，不整套移植，不为可选能力预建框架或增加常驻服务。官方接口暂缺时记录限制，不替换原生系统补齐。

升级目标是保留官方源码原版、原 Agent 身份及原生数据目录，无需合并本地业务补丁或重建 Agent；升级前备份并验证插件兼容性。公开接口变化时只适配对应连接处，不承诺任意未来版本都能无条件直接拉取升级。

规划/审查角色的下游只读执行尚未验收通过，暂不发布主服务绑定。官方随包bwrap已接入，已知历史阻塞为user namespace创建失败；见 executor-isolation.md，不再简单归因于组件缺失。不增加依赖或放宽权限来冒充通过。

## 实施边界

- 本轮拟增加的多项目桥接配置层已停止实施，未部署的代码切片已撤回；先稳定现有常用路径，不让用户为了工作流重新配置一套 Agent、记忆或运行平台。通用项目绑定仍是未完成功能，保留需求记录，不以新增框架代替产品交付。
- 功能接入顺序固定为：先使用 QwenPaw 已有功能，再使用官方插件扩展点，确有接口连接需要时才补充现有外层适配服务。不得为可选增强预先搭建通用框架或新增运行服务。
- 角色、会话、记忆文件、检索和官方自动记忆继续由 QwenPaw 原生实现负责。扩展不注册替代 memory backend，不建立第二套长期记忆正文或来源检索引擎。
- Sim 负责固定流程；插件增加中文入口和受支持工具；外层适配负责节点绑定、Codex 委派、状态、审批与执行证据。尽量复用已有组件，不额外拆成更多运行服务。
- QwenPaw 保持主入口与角色管理入口。流程页面优先复用已有界面和组件；确实缺少中文配置界面时只补所需交互，流程保存、发布和执行仍调用 Sim，不另外维护一套图执行逻辑。
- 审核账本、幂等标识和必要的安全检查服务于原生接口调用，不成为另一套记忆系统。已存在的原生记忆审核、文件读写和受控删除适配保留。
- 某项记忆能力若原生版本尚不能完整证明，明确显示未完成或需要核对，优先跟随官方能力更新。不能改写 QwenPaw 内部数据库、替换记忆引擎或靠永久全角色阻断来宣称已实现完整功能。
- 不承诺任意未来版本无需适配。升级时保留官方源码原版，兼容变化集中在小范围插件/适配模块，并以实际候选版本验证、备份和恢复证据放行。

每项新增功能实现前均核对三个问题：官方是否已经提供、插件是否足够、是否会增加升级时需要手工维护的业务补丁。已能满足需求的原生实现保持原样；暂缺的原生能力记录限制，不通过替换核心来绕过。

SwarmClaw 与 DeepSeek Harness 仅提供可选设计参考，不增加它们的运行依赖。后续功能继续复用现有插件、适配服务和 Sim，不预建多后端框架或额外调度器。此约束不授权删除现有数据、停用原生记忆或绕过已知执行保护。

本次再次收缩实施：不增加安装身份清单、Docker 元数据辅助容器或安装状态机。已准备的这类方案停止实施。必要的启动检查放在现有管理脚本中，只读取原配置、角色和凭证，缺失时提示恢复；不读取或重建记忆正文，不冻结正常会变化的角色配置。Sim 安装级数据保护尚未完成，继续记录限制，不以此为由扩建运行架构。
