# Sim输入数值一致性

Python能精确保存任意长度整数，但Sim的JavaScript运行时不能保持所有大整数。过去的根提交可能先对Python值计算摘要、再让Sim解析时舍入，造成登记值与实际执行值不一致。已在新提交前增加校验，拒绝转换，不把大整数自动改成文本。

共享 `agent_line/sim_input.py` 检查JSON原生值：数值有限且绝对值不超过9,007,199,254,740,991；字符串和对象键能编码为UTF-8；对象键为文本；嵌套最多64层。保留布尔、null、普通数组/对象、合法Unicode和安全数值。小数仍遵循JSON/JavaScript浮点语义，不提供任意精度十进制保证；大整数编号应显式加引号作为文本。

新运行在原归档/发布及角色运行冻结记录之前校验。底层SimJournal在新intent之前再检查规范编码反解析得到的确切发送快照，防止内部非HTTP调用绕过或可变对象在编码后改变。校验失败不会登记新根提交或发原生请求；同事务中的业务任务关联回滚。首次根提交、恢复输入和取消操作均沿原Journal边界，取消的空对象保持有效。

已有同键同输入的记录先返回原回执，不新增intent或发送，不因新数值规则重写旧历史；同键不同输入仍冲突。新规则不能修复过去已经被原生舍入的数据，不能借“修复输入”重发未知任务。历史查询、原恢复核对和幂等观察保留，继续使用原激活/尝试/上下文身份。

静态批量新配方使用共享检查，替代局部仅检查有限数值的递归逻辑；旧batchItem身份/摘要校验规则和正式配方不被改写。原输入复用接口也使用共享检查，减少重复实现。Sim等待点投影在生成角色任务输入前拒绝超安全范围数值，并避免对任意大Python整数调用math.isfinite造成转换溢出；原16层、投影遮罩和体积约束保持。

前端启动表单解析后检查非有限/超范围数字与64层深度，出现问题原位提示把大整数编号改为文本，不发启动请求。服务端为最终边界；没有完整复写浏览器JSON解析器，不承诺保留输入JSON原始排版或非法重复键文本。HTTP新启动/恢复错误使用固定中文422，不回显输入。

改动限原适配仓库：共享输入校验、SimJournal、WorkflowGateway、静态批量构建、Sim等待投影和原前端启动校验。没有新依赖、调度器、数据库、QwenPaw补丁或系统配置变更。AST和源码审阅只能证明相应静态性质，不能替代运行测试或当前完整PRD验收。

本轮遵守不再测试要求，没有单元测试、Node、HTTP、浏览器、模型、lint/typecheck/build或真实Sim任务。已有安全输入、拒绝边界、事务回滚和原记录重放均未运行验收，验收计数保持20/22/13。
