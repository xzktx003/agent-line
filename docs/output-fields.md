# 自定义节点结果字段

在流程搭建中选中Agent节点，将结果格式改为“自定义字段（JSON）”。逐行填写字段名，选择类型，勾选必填；应用节点配置后保存草稿、再发布。新角色不因此创建，记忆仍由原QwenPaw管理。

例如声明summary（文本，必填）、approved（布尔，必填）、score（数值，可选）后，Codex正文应为单个JSON对象：

```json
{"summary":"完成审查","approved":false,"score":0.7}
```

条件节点选择该前置Agent的approved字段，与布尔false比较即可。字段路径为`result.output.result.approved`，由原Sim执行判断。条件只允许必填的标量字段，可选字段用于结果展示或传递；缺失字段不自动当作false。Agent的approved只表示意见，不代替人工审批或独立测试。

## 契约与边界

节点配置为`outputSchemaId: "fields-result-v1"`，并附加`outputFields: {"fields":[{"name":"summary","type":"string","required":true}]}`。字段1–32个，名称以ASCII字母开头、后接字母数字下划线，长度最多64，不能重复或使用constructor/prototype/__proto__。至少一个必填。定义不接受额外配置项。

支持文本string（最多4000字符）、布尔boolean、有限数值number、整数integer、字符串数组string_array（最多100项，每项2000字符）；字符串禁止NUL，数值绝对值不得超过9007199254740991。必填字段必须存在，可选字段可省略但不能用null冒充该类型。结果禁止额外键/重复键、非有限值、无效Unicode；JSON正文上限64000个UTF-8字节。整段正文恰好是单一 Markdown 围栏且内部为原 JSON 时，只投影该正文，不改已保存原文；其他围栏或说明仍无效。数组与可选字段不提供分支比较，必填标量的比较类型需匹配声明；整数与数值都按JavaScript数值域比较，可使用小数阈值。自定义结果条件禁止引用未声明路径及原始text/nativeStatus，只保留正式验证状态与声明的必填标量。当前是明确的扁平对象契约，嵌套结构、任意JSON Schema、枚举或用户调整长度限制尚不支持。

编译图完整保留定义；发布Agent策略与运行账本冻结同一内容，后台发现任务复制冻结定义。直接节点登记支持同一字段定义，缺少有效定义只允许精确已有记录重放，不接受新任务。旧请求没有该字段时不插入null，不改变旧幂等摘要。原task-result/coding-result-v1/review-result-v1语义不变。

委派前按冻结契约追加原任务指令，不启动额外模型调用。结果只在有效时派生structuredOutput，并在原Sim回传output中加result；原始正文、身份、验收/资源退出/记忆策略和未知提交守卫不变。已保存的原回传按原冻结结果核对，不重投。

前端只提供后端已声明且本地支持的格式；旧后台不提供新ID时保留原配置并禁止应用、保存或发布。非法或未知字段定义不得静默清除，切换格式也必须明确应用才改变本地草稿。无新依赖、数据库、调度器、常驻服务或上游业务补丁。
