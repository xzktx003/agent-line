# 业务任务与运行关联

对应PRD Mission/13.7：在现有SimJournal.operations保存不可变业务任务目标、验收条件与独立命名空间中的运行关联，无新表、迁移、服务或调度器。业务任务本身不代表已运行或已通过验收。

- 使用现有工作流服务身份与项目scope提供项目/业务任务登记、列表、详情和关联运行目录；目标正文仅授权接口可见。初版定义不可变，同一ID相同内容幂等，不同内容冲突；修改目标应新建任务，旧运行证据保持。
- StartRequest可选workItemId；绑定项目在服务端核对，缺字段保留旧Sim输入/触发身份/幂等摘要。业务任务关联与根运行首次intent在同一SQLite事务落盘，旧运行不得事后关联，关联运行不得以缺字段或其他任务重放。resume/cancel和旧原生输入不加业务字段。
- 关联快照包含任务定义摘要与原输入摘要，读取时核对项目/绑定/原运行；仅新关联任务通过既有发现/登记链把同一上下文送给原角色与Codex。文本验收条件不变成可执行命令，不替代原独立验收策略或人工批准。
- 原生Sim负责图执行，任务API仍保留激活/attempt/原生身份，关联元数据不推进任何状态。历史无关联记录继续无关联；未知提交仅观察原身份。
- 在运行管理增加业务任务选择/登记/关联运行目录，不新建管理平台；选用后显式启动，一项业务任务可对应多个显式运行。首页只展示业务任务标识，目标与验收正文不进入无认证摘要。
- 不新增或运行测试、Node、浏览器、HTTP、模型/探针或lint；仅源码/AST与Luna静态复核。没有真实业务验收前不提升AC。部署只复用原备份/空闲/维护保护重载，不改上游或原生记忆。
