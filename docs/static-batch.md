# 从数据清单创建静态批量流程

流程搭建页选择项目并读取角色后，展开“从数据清单创建批量流程”。填写新流程名称、既有角色、共同任务说明、数据清单及完成条件。普通模式每行一项，忽略空行并保留非空行原文字；高级模式接受完整JSON数组。当前支持静态2–20项，每项规范JSON最多1200字节，共同指令最多2000字符，完整配方64000字节。较长数值标识请用字符串，浏览器拒绝非有限/超安全范围数字，避免序列化变null或不可靠大整数。

点击创建后，先通过原项目编辑授权的POST `/extension/v1/authoring/projects/{project}/batches/preview` 本地校验，再复用原创建草稿API。预览不访问原生服务、不写库、不创建Agent、不保存或发布；成功回执no-store。返回项目/配方身份、输入指纹与确定性节点映射及原schema1图。客户端核对逐项身份、角色、策略和配对拓扑后才提交创建。

创建成功只读核对目标确为空白，再将配方载入本地画布。之后还需手动保存草稿、单独发布和启动。原草稿有未保存修改时先按原丢弃确认；预校验失败保留原图。创建结果未知保留原operation/copy快照，只查询原操作，不自动重投、保存、发布或运行。退出/换项目清表单，epoch防迟到覆盖。

## 如何执行与追踪

配方展开为开始→并行分发→每项Agent→汇合→结束，全部为已有编译器支持节点，继续由Sim推进。项序号、itemId和输入SHA256写入本项冻结指令；原数据以明确JSON数据段附在共享说明后，不授予额外权限。各项有独立nodeId、激活、任务与attempt；复制或重新发布遵守原图版本及任务身份规则。item/node标识由recipeId、序号和输入指纹确定，同值的不同序号仍是不同项。

角色只选择当前项目已启用的既有绑定，所有项复用其正式Agent和原生记忆，不增殖角色或复制记忆。各项仍须通过已有发布能力与独立验收策略，配方文本不提供权限或真实验收保证。

“所有项独立验收通过”使用原all_success汇合；“允许部分失败”使用原allow_partial，仍需至少一项独立验收通过。都等待全部分支结束，保留各项原执行/验收结果，失败不自动成为新尝试。输出为原汇合的agentLineResult/output.branches，键为各项逻辑nodeId，可从已发布图中的对应节点和冻结指令追溯项身份/数据指纹；不丢弃失败分支。

图的并发上界设为项数，真实编码仍受原角色/工作区租约、FIFO及运行额度限制，同一角色或工作区可能串行，不宣称20项同时编码。requireMemoryCommit默认false，记忆状态仍独立，数据及结果不另存新账本。

## 范围与当前证据

数据清单随保存/发布固定，不是从运行时输入动态扩展的批量节点。暂不支持动态列表、嵌套批量、单项模式或批量与有限循环混用；完整R17、AC31/33仍未完成。用户数据可能含路径或秘密，会留在指令/流程版本中，创建前需核对，本功能不自动脱敏。

仅源码阅读、两个Python AST和Luna静态复核，无测试、Node、HTTP、浏览器、模型、lint/typecheck/build。未向真实Sim创建或执行批量流程，不以部署成功代替行为、并行或业务验收。AC不提升，完整PRD继续实施。

新配方的结构化批量项随冻结策略和任务输入保存，编辑器保留只读项数据；旧配方不回填。结果摘要与私有详情的边界见[批量项追踪](batch-item.md)。
