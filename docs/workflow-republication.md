第一次探针错误要求恢复子运行一定有独立 `/logs` 记录；实际子执行接口存在，
但子日志返回404。官方持久根日志已完成，并保留原 deployment、图和最终输出。
探针改为核对确切的根日志与历史发布定义，再与实际子执行输出互证，没有重跑旧任务。

日志的图投影不含 variables，并给边补充 null 的 sourceHandle/targetHandle。
当前探针明确限制发布 variables 为空；先核对历史发布的图指纹，再精确比较根日志
全部 blocks/loops/parallels/edges，仅将两个空 handle 与缺省等价处理。未知图字段、
非空变量、错版本、换指令、改分支、未完成或不同输出均不能通过。

## 现有超时配置修正

180秒来自早期接入验证的插件配置，并非 Codex Harness 的默认限制。
现仅调整已有两个字段：

- `plugins.agent-line.execution_bridge.timeout_seconds`：180 → 3600。
- 执行配置中既有 gateway 的 `parentTimeoutSeconds`：900 → 3600。

继续通过官方后台任务的 timeout 字段执行有上限的预算。使用官方插件安装接口
重新加载原插件，QwenPaw 宿主未重启；9个Agent配置、角色版本、记忆后端及其余
配置保持。初始化桥配置探针同步采用3600，避免再次留下180秒默认。

调整前备份原配置与原17条任务。独立启动后验收
`task-355f652e4fee4d7eb8754ba6b9e2fd7c` 真实调用Codex、三个独立测试通过，
原17行保持，重新生成当前执行证据后恢复原主服务入口与准入。
随后才以明确的新幂等标识启动上述版本2正例；它不是原超时任务的自动重投。
