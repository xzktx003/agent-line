# 多阶段静态并行与汇合

同一流程可配置最多10组“并行分发 → Agent分支 → 结果汇合”，例如第一组分析任务汇合后连接第二组审查任务。每组仍2–20个Agent，整个流程最多200个节点。仍只支持每个分支单个Agent的静态结构，不支持嵌套分支子图、动态分发或与有限循环混用。

每个分发必须明确选择自己的汇合，汇合须反向选择同一分发；同一Agent节点不能同时属于两组。分支只允许来自本组分发的一个入口和到本组汇合的一个出口，无旁路。每组独立选择全部成功、允许部分成功或指定必选分支成功；失败输出须由Agent配置显式允许，未知/未验收结果不默认为成功。

后续Agent可选择前置汇合输出作为输入，条件和结束节点也可引用前置汇合。普通来源仍须是所有到达路径必经节点；只有本组已验证的汇合可直接引用其分支结果，其他组不能借用这一例外。正常依赖无环、可达、角色/记忆/独立验收及执行权限约束保持。

编译器复用原AL_PARALLEL_V1/AL_JOIN_V1 marker和固定生成代码，逐组验证后编译为原Sim函数和边。原单组文档不增加新配置字段。发布与运行核验也允许同一常量界限内的多组，并对全部原图重新解码和编译核对。运行仍冻结原发布定义、角色策略与任务身份，Sim是唯一图推进方；没有新增调度器或数据库。

固定Sim检出源码的human-in-the-loop-manager.ts中，恢复执行为新暂停保留metadata.executionId=parentExecutionId，persistPauseResult按该durable ID合并旧/新pausePoints并累计计数；getPausedExecutionDetail按原executionId读取。原发现器逐项匹配已发布节点，任何后阶段paused/queued/resuming点或未终态的恢复执行都阻止静态终态确认。这些是源码依据，不代替实际多阶段执行和重启验收。

项目roles目录提供maxStaticParallelGroups；编辑器仅按明确能力允许多组，旧后台缺失或非法能力按原1组处理，超能力原图保持只读。旧批量生成预览仍严格核对单组形状，不把新能力用于放宽返回值身份验证。每组maxConcurrency仍不小于分支数；它不是任意全局运行限流器，任务还受原项目准入和工作区租约限制。
