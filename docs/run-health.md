# 本地运行检查

运行管理的“查看运行”表单新增“只查本地记录”。填入原绑定和运行标识后，读取当前项目/工作流/run的原任务、事件和租约，独立于Sim连接是否可用。不会启动新任务、主动原生探测、调用模型、取消、恢复或重新提交。

原授权 `GET /extension/v1/workflows/{bindingId}/runs/{runId}/health` 先按既有绑定和原提交日志核对运行归属/固定发布，再读取同一TaskStore SQLite快照。成功响应no-store，source为local_run_health、readOnly为true。原运行查询同时附加同样的health摘要；它仍按原语义查询原生状态，本地按钮才是不访问Sim的独立入口。

摘要分开统计排队、执行/资源收尾未确认、资源退出未确认、成功执行后待验收、验收失败、记忆等待处理/失败、原执行最近核对未知/缺少记录、较长时间无新本地事件及工作区租约。各项可以重叠，不相加为任务总数。注册队列不算已提交执行，资源未退出不能当作已停；零本地任务不证明原生图未运行或已完成。

固定300秒只作展示窗口：对执行/资源收尾或独立验收待处理任务，检查最新非execution_observed/execution_observation_unknown事件距当前读取的时间。超过窗口只表示“没有新本地非观察事件”，不表示Codex无进展、进程失联或执行超时。事件时间缺失/非法则记activityUnknown，不计成安静。原观察事件只在状态变化时登记，其时间不是最近巡检时间；nativeProgress和codexActivity均保持unknown。

后端没有写新事件、改变准入、自动修复、调度或建立第二套事实库。payload/状态/计数无法可信核对时返回unknown、计数为null，不能当作零。当前运行范围受原项目授权保护，不暴露宿主路径、任务输入/输出、证据、其他项目标识或秘密。

原运行查询的检查面板默认折叠；主动点击本地按钮则展开。换运行/身份/模式或重新查询清旧结果，迟到响应由原查询generation隔离。旧后端缺字段兼容，本地接口404不会自动降级成其他项目或新运行。

本轮只做源码/AST/Luna静态复核与维护重载的保留核对，没有测试、Node、HTTP、浏览器、模型、lint/typecheck/build。实际断连恢复、完整空闲巡检和AC69验收仍未完成，不提升AC状态。
