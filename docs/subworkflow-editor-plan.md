# 子流程编辑入口计划

把已有真实preview/save/publish接到原macOS编辑器，不另建工作流平台。默认折叠“插入固定版本子流程”：先保存当前父草稿，列表选择同项目流程/明确历史版本，再选已有连线和父输入来源；可选字段映射，显式预览/核对/加入本地草稿，再沿原保存/发布。无自动运行/角色创建/预算修改，所有请求原内存凭证。

独立subworkflow-editor.js负责候选/版本分页、映射字段行、预览及加入，迟到/切项目/退出/输入变动丢结果。editor.js负责能力声明、原状态/dirty保护、识别固定片段和内部节点只读、整体移除与原来源选择/验证；不允许直接添加两wrapper节点。固定成员可视觉布局但不能单独改配置/删除或改内部边，入口/出口连线可按原受控编辑处理；服务端validate_groups仍为权威。

服务端额外收口数据引用边界：外部Agent/条件/结束/其他子入口只能引用子返回出口，不得绕过outputMapping直接引用固定内部节点；允许同父图多个单层调用按output端口串接。保持nested来源拒绝，不假装增加递归深度。旧后台缺能力保持包装图只读，不把未知配置删减后保存。

静态审查调整：涉及固定组的入口/出口连线也不能单独删除或重建，避免丢失组识别及服务端固定出口边身份；使用整体移除后重新预览。存在其他固定组输入依赖时，先移除依赖组；普通节点悬空引用保留并由原表单修复。最终行为以此及subworkflow-editor.md为准。

后续边界修复：内部边从数量/闭包识别进一步核对原sourceDocument映射后的每一条source/target/branch；删除普通节点前检查固定组入口/出口邻接或inputFrom依赖，拒绝造成固定组断裂的删除并给出整体移除重插提示。只做源码/静态复核，不运行测试；不修改原执行或暂停守卫。
