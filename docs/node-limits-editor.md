# 编辑器中的节点执行限额

状态：2026-10-23源码接通，后端已按原配置重载装入主服务，尚未做功能验收。没有新增测试或执行测试。

Agent节点可以勾选“自定义节点限额”，填写执行时限与最大实际提交次数。时限为严格整数1–86400秒，次数为严格整数1–100。未勾选时图配置省略limits，自动任务发现沿用3600秒、3次；不会给旧图、旧发布或历史任务补写字段。

例如节点config可以额外带有：

```json
{"limits":{"maxExecutionSeconds":1800,"maxBusinessAttempts":2}}
```

该字段与角色绑定、指令等一起保存在原图的Agent规范中，经现有发布策略与运行账本冻结，再由任务发现传入现有TaskStore限额机制。改草稿不改变旧运行额度；旧发布未声明limits时仍采用既有3600/3。无数据库迁移、新服务、新依赖或QwenPaw/Sim源码补丁。

次数是同一项目/工作流/运行/节点的实际提交意图总额，循环和业务重试共同消耗；不是自动重试次数，也不是模型工具调用次数。失败、取消及受理未知不退款，确认尚未提交便取消不消费。循环上限可能高于次数配额，届时由已有准入机制阻止新提交，任务保持已登记，需要人工处理或停止流程；不会自动变成失败分支或静默增加额度。Sim继续决定图的循环/分支，不因这个配置增加另一套重试引擎。

时限从每次持久submission_intent起算，不包括排队等待；到期通过现有观察/取消链路申请停止，不承诺到秒退出。确认终态和原生资源退出前仍保留身份与租约。完整规则见[执行限制](execution-limits.md)；跨节点的可选运行总预算见[运行预算](run-budget.md)。token、金额和完整父角色用量缺少可信来源的部分仍未知。

编辑器只在已授权roles响应明确声明nodeLimitsSupported:true后允许自定义。旧后端没有声明时不猜测支持，不静默删除原图已有字段；旧图未带字段可以照常编辑。服务端图校验、运行账本和任务发现分别核对范围，非法值不回退默认值来执行。
