# JSON 流程模板导入与导出

在流程搭建页打开可编辑草稿，展开“JSON 模板 · 导入与导出”。不新增页面、依赖、服务或模板数据库。

## 导出

先应用尚未应用的节点表单，再点“准备导出当前草稿”。原项目编辑授权接口只在本地编译校验当前逻辑图，按Agent绑定首次出现顺序替换成slot_1等抽象角色槽位。页面展示待下载JSON，核对内容后勾选确认，再下载。导出包括当前本地尚未保存的图，不会自动保存或发布。

模板不自动附带项目、工作流/发布/运行身份、凭证、宿主路径、角色Agent身份、会话、历史、产物或记忆正文。逻辑节点/连线标识保留用于图内引用；原编译器按目标工作流命名空间生成不同原生节点身份。节点指令、名称、条件字面值及结束固定输出是用户编写内容，会原样保留，可能含自行写入的路径或秘密，需要用户核对；不能将本功能称为自动脱敏。前端额外阻止把当前编辑凭证原样放入模板请求。

## 导入

先选择项目并打开目标草稿（可以先按原入口创建空白草稿）。选本地JSON文件，页面先在本地读取节点/连线/槽位摘要。为每个角色槽位显式选择当前项目已有角色；不按名称自动替换，不创建Agent。多个槽位可选同一角色，这不产生独立审查权限，用户仍需核对职责。

点“校验并载入当前草稿”才发送模板与映射到原授权服务。服务精确核对格式、槽位顺序/覆盖与映射、当前项目启用角色和原生记忆策略，替换后再次调用原编译器校验；没有原生HTTP、数据库写入、模型或图推进。有效结果仅替换本地画布；存在未保存编辑时按原丢弃确认保留选择。之后必须显式点击原“保存草稿”，发布仍是独立操作。

导入失败、取消替换、请求超时或迟到响应保留原草稿。换项目/身份/工作流、修改图或未应用表单、刷新角色会清临时文件和映射；不存localStorage。编辑器改变图的原操作仍可进行，迟到结果不能覆盖新图。

## 格式与边界

精确顶层为format、schemaVersion、document、roleSlots，format固定agent-line-workflow-template，schemaVersion整数1，document沿用逻辑图schema1，roleSlots按首次使用顺序为{id:slot_N,name:角色 N}。只接受当前编译器支持的节点及native-role记忆策略，最多200节点/1000连线/200槽位，模板、源图和映射后的结果分别受256KiB规范JSON上限保护。

原项目编辑授权POST `/extension/v1/authoring/projects/{project}/templates/export` 接{document}；`.../templates/import`接{template,roleBindings}。两接口只读，成功响应no-store，但仍受原POST兼容保护，保护中可能返回503，不绕过权限或维护策略。旧后端404不会改变本地图。

当前只交付JSON模板分享及显式角色重映射，不代表完整跨安装迁移：不搬迁角色配置、账号、工作区、记忆、历史、上游数据或秘密；也不实现子工作流递归/固定依赖，见subworkflow-source-boundary.md。

仅源码阅读、Python AST及Luna静态复核；没有测试、Node、浏览器、HTTP、模型、lint/typecheck/build，不据此标记P2/AC67完整通过。
