# 业务任务与关联运行

在“运行管理”的“业务任务”区选择项目，可登记名称、固定目标和1–8条验收条件。登记只保存任务定义，不创建Agent、不启动工作流。选用任务后，启动同项目工作流时关联该任务；另一次有意发起的运行使用新的触发标识，仍可选用同一业务任务。

定义创建后不可修改。同一任务标识、相同内容可识别为原登记；修改目标需要新任务，旧运行不会被重写。登记回执不明时保留原内容与标识，只提供读取原记录的核对操作；退出、刷新页面会清除页面内草稿，应从已登记目录核对原记录，不能因为没收到回执就认为未保存。

“查看关联运行”展示本地提交状态，不代表原生执行结果或业务完成。点击查看只填写原运行查询表单，需要再次点击查询才读取状态。运行详情和节点任务详情显示固定目标与验收条件，原三类执行、验证、记忆结论分别保留；文字验收条件不会转为执行命令，也不替代既有独立测试与人工审批。

“查看节点任务”直接按当前项目和业务任务读取原任务中心，跨多次运行显示已经登记的节点及独立状态；不改变已选启动目标。详细范围和分页语义见[业务任务节点目录](business-task-directory.md)。

## 实现边界

- 使用既有SimJournal的operations表，在独立命名空间保存不可变定义和运行关联；无新表、自动迁移、服务、依赖或调度器。
- 定义和目录沿用原Bearer认证、项目scope与启用状态；匿名首页仅增加业务任务ID，不返回目标与验收正文。无关联的直接节点登记拒绝保留字段input.workItem；已关联的上下文由服务端查原记录并冻结，不信任客户端声明。
- 关联与根运行首次提交intent在同一事务写入，提交前持久化；原Sim输入和原触发身份不因可选关联字段改变。旧运行不能事后关联，已关联运行重放必须提供同一任务；省略、更换任务或输入变化均冲突。未知提交仍只核对，不自动重投。取消、恢复不增加新的业务任务定义。
- 节点发现与直接登记复用原关联，将固定目标送入现有角色/Codex任务输入；保留官方Agent、会话与原生ReMe，不复制或替换记忆系统。
- 目录核对原运行输入摘要、关联作用域、定义摘要、提交状态与时间。损坏记录拒绝展示；无法解析且无法确定项目的关联记录会保守阻断关联目录，避免当作无关联记录跳过，不自动修库。
- 当前任务关联尚不提供业务完成状态自动聚合、任务定义编辑/删除、负责人变更、里程碑或子工作流递归预算。完整PRD仍未完成。

仅源码阅读、Python AST解析及Luna静态复核；未新增或运行测试、Node、浏览器、主动HTTP、模型探针、lint、类型检查或构建。不得将这些静态证据作为实际业务验收。
