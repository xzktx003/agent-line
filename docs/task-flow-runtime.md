# 原生 Agent 节点与后台结果回传

QwenPaw 继续保存角色、会话和原生记忆；Sim 继续决定当前节点和后继路径。扩展只把
一个已经发生的原生机器等待关联到一个角色任务，并将已验证的结果返回原暂停上下文。
这些组件都在现有适配进程内运行，不新增服务。

## Agent 节点表示

中文文档新增 `agent` 类型。编译器将其转换成原生 Human 机器等待，并明确与真正
的人工审批区分。节点配置包含既有 roleBindingId、任务模板、输入来源、原生记忆
策略、结果结构标识，以及是否等待记忆提交/允许失败结果进入后续路径两个布尔策略。
不创建正式 Agent、不存工作区和机器凭据。

输入来源只能是开始输入或必经前序 Agent 的输出。原生 Sim 解析实际输入；任务模板
等固定配置以编码元数据保存，避免把指令中的模板字符当作 Sim 的变量引用。服务端
从项目角色登记表确认 roleAgentId，浏览器不能自行指定执行角色或目录。

保存和发布会检查既有角色绑定；成功回执附带 `externalTasks`，记录发布版本、原生
等待节点和固定任务策略。当前中文入口仅提供默认 `native-role` / `task-result`，
不通过自定义策略名启用另一套记忆引擎。角色列表表示服务端配置，不冒充原生实时健康。

## 服务接线

已有 service.json 可以选配 `taskFlowFile`，其私有配置严格为：

```json
{
  "schemaVersion": 1,
  "runLedgerPath": "/absolute/private/workflow-runs.sqlite",
  "pauseBindingsPath": "/absolute/private/pause-bindings.sqlite"
}
```

两个账本必须是已经显式初始化的不同存储，权限 0600；启动不创建、重建或迁移。
WorkflowRunLedger 继续使用 schema 1，机器策略存入已有快照列；不另建图存储。
角色绑定沿用已有 service bindings，Sim 连接和提交日志也复用原实例。

受信任的 `sim.bindings` 通过 `externalTasks` 关联一个已核验的发布版本。开始运行时
先检查原生发布图、冻结策略，再登记出站执行意向。重放不得改变角色策略、TTL 或
发布版本；原始 resume 入口不能绕过机器任务回传，即使后续配置删除了 externalTasks。

`load_app` 仍不能凭一个配置布尔值声明受控执行已经确认。正式准入、完整部署和
新建流程自动加入运行列表已接通发布目录；真实集成探针的 confirmed 仅属于其独立
受控环境，不改变主服务守卫。

## 后台生命周期

1. `ExternalTaskDiscovery` 只处理冻结 Agent 策略中的机器等待；人工审批发现器只处理
   显式人工范围。混合流程共用一条运行记录，旧机器运行不会自动获得审批权限，见
   [混合流程](mixed-workflows.md)。
2. 核对实际运行版本，再通过原生 selectedOutputs 读取持久化的 taskInput。缺失、隐藏
   或无法确认输入时保持等待，不能从展示 trace 或静态模板猜测。
3. 原生暂停身份决定幂等任务身份；项目、角色和执行目录从服务端解析。登记后中断、
   尚未来得及保存暂停关联时，下一轮复用原任务补齐关联，不创建第二个任务。
4. 现有 ExecutionWorker/Dispatcher 调用 QwenPaw 协调角色，由其真实检索记忆和委派 Codex。
5. CompletionWorker 复用 CompletionRelay，等待独立验收、资源退出和所选记忆提交策略。
   任务先完成但 Sim 尚未暂停时继续核对，不立即提交恢复。
6. 只恢复原 workflow/run/context，实际后继由 Sim 执行。出站恢复意向持久登记；丢失
   回执和重启后不自动重投。

原生 pausePointCount 包括已经恢复的历史节点，因此以总数减已恢复数等于一判断
唯一活动暂停；同时保留发布图和准确 context 核对。无循环策略仍要求单激活；
显式有界循环走独立形状证明和逐轮前驱核对，见 [循环任务接线](loop-task-runtime.md)。

关闭应用时先通知所有后台循环停止，再等待当前操作退出；仍有线程占用连接时
报错并保留连接，不把停止轮询说成原生执行已停止。

运行级暂停/停止门禁现覆盖登记、出队及新结果回传；活动任务仍可观察退出。
既有发现器还会补齐“停止已落账、取消尚未发出”的恢复窗口，已有未知意向绝不重投。
具体语义与真实证据见 [流程控制](run-controls.md)。

## 已验证范围与限制

实际对象输入、两个顺序机器等待的传递见 [原生等待探针](sim-agent-wait.md)；真实单
Agent 自动登记、Codex、文件验收和后台恢复见 [自动工作流探针](automatic-task-flow.md)。
原生记忆的跨任务检索、委派和审核写回另见 [记忆闭环](native-memory-roundtrip.md)。
三种证据分别覆盖各自范围，不能相互冒充完整多节点业务验收。

selectedOutputs 使用上游秘密安全投影。HTML 和普通业务字段保留为任务数据，但
`{{NAME}}`、秘密脱敏标记和未物化大值引用仍不能当作完整输入；此时拒绝登记。
原生投影无法区分某些字面模板与秘密占位符，这是当前限制，未通过绕过官方边界解决。

新建流程自动绑定、Agent 结果条件与限定循环接线已实现；完整多 Agent/复杂循环、
混合人工审批发布、通用测试验收和正式准入仍待交付。公开 execute 仍只执行当前
active deployment，发布前检查不是原子版本锁；不能宣称任意历史版本均可固定执行。
