# 静态批量项追踪

新建静态批量流程时，每个 Agent 节点保存可选 `batchItem`：配方标识、1–20 序号、稳定项标识、标准 JSON 输入和 SHA-256。指纹按原有 canonical JSON 计算，单项输入最多1200字节；逻辑节点身份与配方、序号、指纹共同派生。编译与运行策略登记核对项身份和对应原生节点，原发布配置编码自然保留该字段。

任务发现从冻结运行策略取数据，写入任务输入和登记载荷。TaskStore 在幂等哈希/写库之前核对两个副本和原生节点；执行指令生成前再次核对。直接节点登记不能代替已冻结批量节点的发现流程。沿用既有激活/尝试、角色、工作区租约、原生记忆、验证与结果回传，不额外创建 Agent。

回传结果增加仅含配方、序号、项标识、输入指纹的摘要；原结果日志恢复核对同一摘要，结果不能与另一数据项混用。输出本身仍遵循原结果契约；汇合输出沿用原节点ID映射，没有新增动态展开器。

私有任务详情展示完整本项数据，目录仅带摘要；匿名首页保持既有字段白名单。编辑器批量数据默认折叠只读，应用角色/指令等修改时保留该字段。更换数据应重新创建批量流程；用户输入可能含私密内容，模板导出前仍需自行核对。

旧发布图、运行或任务没有此字段时保持原格式，不从自然语言指令推断身份，也不回填旧记录。静态配方仍仅2–20项，动态运行时列表、嵌套批量与实际执行验收仍未完成。

本轮只做源码审阅与九个 Python 文件 AST 解析，未导入应用执行行为，没有测试、Node、HTTP、浏览器、模型、lint/typecheck或构建。尚不能据此宣称真实批量业务执行已验证或完整PRD已完成。
