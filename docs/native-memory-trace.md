# 原生记忆召回与委派快照

任务详情增加默认折叠的“原生记忆召回与委派记录”，显式点击“读取已有快照”才读取。原授权GET `/extension/v1/node-tasks/{taskId}/memory-trace` 先核任务项目范围和既有执行网关，再只读原RoleDispatchLedger保存的父角色快照，没有原生HTTP、模型、记忆召回、结果回写或新事件。未接入的后端返回503，不按相似角色替换。

## 能核对的事实

父任务快照必须匹配原ledger parentTaskId，角色/会话/deployment必须匹配原网关和任务。只识别原生plugin_call/plugin_call_output中的memory_search和agent_line_delegate，按call_id严格配对，拒绝重复调用/重复或悬空输出、非法参数和超限快照。快照最多2MiB规范JSON、2000消息/10000内容块、每种工具100次；失败整体unknown，不用前半段冒充完整摘要。

召回展示调用标识、参数SHA256、原工具结果状态和结果SHA256；委派展示指令UTF-8 SHA256、结果状态、是否匹配当前任务及原生upstreamTaskId，以及在委派前已成功返回的召回调用。缺失原执行身份时匹配为null，不把空值相等当成功。明确矛盾为false，仅说明回执关联失败，不改实际执行状态。未记录工具结果与工具错误分别显示。

只输出标识和指纹，不返回查询词、结果、委派指令、记忆正文、宿主路径、凭证或原始异常。原有父快照仍在原提交账本，未增加正文存储、索引、长期记忆引擎或来源权威库。

## 证据的界限

memoryInjection始终unverified：先成功召回再委派只是顺序证据，不能证明相关记忆内容确实进入Codex输入，更不能证明有效、正确或跨会话复用。实际闭环仍按原生执行/召回/实际Codex输入核对，不因面板出现指纹提升AC。

coverage固定cached_parent_snapshot，成功解析也不宣称全部历史或完整上下文。未知快照的searches/delegations为null，不显示零调用。成功解析的空列表只表示此快照中未记录，不证明没有执行。

原账本没有快照抓取时间，snapshotCapturedAt为null；readAt仅本次本地读取时间，不表示原生活动、最近巡检或原生记忆最新状态。用户仍可用已有父任务/角色会话标识在QwenPaw原生界面核对正文。

前端核任务/角色/会话、来源、状态、指纹和召回引用；换身份/任务/刷新详情使迟到响应失效，不存浏览器持久化，不自动读取，不打开不可信链接或执行文本。任务执行、验收、记忆状态仍独立。

本轮仅源码/四个Python AST/Luna静态复核和原维护重载保留核对，无测试、Node、HTTP、浏览器、模型、lint/typecheck/build。未重新采集原生快照或安装插件，完整记忆追踪/注入/恢复验收仍待完成，AC不提升。
