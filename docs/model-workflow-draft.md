# 自然语言生成流程草稿

从流程编辑器模板库选择“自然语言流程草稿”，选择当前项目已配置的只读规划角色。配方要求角色元数据为 planner / readonly，原执行描述明确 read-only 沙箱和 never 审批策略；这不是新的权限来源，发布仍经过原角色、沙箱和就绪检查。当前只读运行尚未通过时继续拒绝发布，不能以模板存在认定功能已可用。既有隔离记录已确认官方随包bwrap存在并接入；已知阻塞是当前环境下user namespace创建失败，不应再将其简单描述为缺少组件。见 `executor-isolation.md`，本轮没有重跑该历史探针。

保存、发布后，用户通过原运行入口提供自然语言需求。原QwenPaw角色保留原生记忆与Codex委派链，结果声明为 `workflow-draft-v1`。没有另建模型服务、角色或调度器，没有自动发起模型调用。

新结果格式接受完整 `agent-line-workflow-template` 信封，使用原模板校验与编译器；角色仅能是按首次使用顺序排列的占位槽，原生记忆策略必须为 native-role。原始JSON与规范模板各限64,000字节；原节点、连线、位置、类型与条件约束保持。固定子流程引用和静态批量身份不允许由此格式生成。结果格式是数据契约，本身不强制调用者拥有规划权限；规划模板和原角色发布检查承担各自责任。

成功且资源已释放任务的详情中，展开“生成的流程草稿”，点击“核对草稿”。`POST /extension/v1/node-tasks/{task_id}/workflow-draft` 使用原运行Bearer凭证和项目范围，正文仅为严格 `expectedVersion`。版本变化、未结束或无有效草稿均拒绝；编译后再次读取原任务并核对版本、输出和状态。返回来源 `validated_model_workflow_draft`、任务/项目/版本、节点/边/槽数量、规范模板SHA256和完整模板，响应no-store。

接口不提交任务、不读写Sim、不写记忆、不执行独立验收。`verificationStatus` 保留原结论，结构核对并不要求或产生“验收通过”。原兼容降级对POST的拒绝规则保持，因此降级实例可能返回503。并发更改后重新查询原任务，不自动重试。

前端逐字段核对回执与原结果，展示完整脱敏JSON，检测当前凭证文本时禁止下载。用户明确勾选核对角色、分支和指令后，才能下载候选模板。下载不等于保存或发布，需在编辑器JSON模板区手动导入、绑定已有角色，再分别保存/发布。正文不进入URL或浏览器存储，没有自动导入或跨页执行。

本批仅源码阅读、独立Luna静态复核和标准库AST语法解析；未运行测试、Node、浏览器、HTTP、模型、lint/typecheck或构建。后端已按原配置空闲重载（见 backend-rollout-workflow-draft-20261023.md），接口和完整生成路径未实际验收；不能据此宣称P2或完整PRD完成，AC计数保持20/22/13。
