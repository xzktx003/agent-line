# 技能候选交接计划

目标：把已提交且未删除的人审经验转成 QwenPaw 原生创建接口可接受的、默认禁用的技能候选，保留项目、角色、任务与审核证据。普通事实仍走原生记忆；工具步骤须由有权限的人明确编写，不从模型输出自动提取。正式安装与启用继续由原生技能管理负责，不增加服务、权限体系或长期内容库。

范围：增加纯格式化模块和现有记忆 API 的候选导出入口。仅授权项目原审核可导出，要求期望正文摘要、已提交状态、无删除记录且内容与审核一致；读取在原记忆作用域下与删除串行。候选包含独立人工补全的名称、描述、版本、适用/失效条件、操作边界和步骤；原经验只作为出处参考。

原生交接：返回创建请求 JSON，`enable=false`、`scripts=null`、`references=null`、`config=null`；调用方仍须通过原生身份和固定目标角色安装，再由原生安全扫描和启用流程决定是否可用。扩展不调用创建/启用接口，不写原生文件。候选导出不等于发布或完整 AC-67 验收。

源码调研发现原生限制：`_register_workspace_skill_entry` 保留旧 manifest 中同名技能的 enabled，因此文件目录已丢失而旧配置仍启用时，`enable=false` 不能保证实际禁用。安装前须确认新名称没有遗留配置，安装后核对实际状态；本增量仅导出，不可据此开放自动安装。原生安全扫描也受宿主配置影响，不能声称总能阻断。

静态审查：校验字段、大小、YAML 字符串转义、来源身份/摘要、墓碑与重复导出无写入；只读官方接口源码和 Python AST，不运行任何测试、模型、浏览器或探针，不新增测试。

本轮补齐：在原记忆页增加技能候选字段、人工确认和JSON下载，沿用凭证/epoch/退出清理。增加只读skill-status核对：从相同原审核重建候选，再以绑定角色读取原生详情，比对完整文本摘要与真实enabled；网络前后重新验证原审核和墓碑，网络期间不持有本地锁。404仅表示未观察到，不能证明名称可安全创建；不自动安装、启用或修正原生配置。
