# 任务登记、开始时间与最近事件摘要

PRD13.7的任务中心时间和事件展示接到既有 TaskStore。首页任务列表、运行管理任务列表及任务详情显示“登记时间”和“最近记录”（最后持久事件时间与中文类型）。新读取会带 `activity.startedAt`：只有已保存的 `role_started` 才填最早发生时间；没有这条事件时是 `null`，页面显示“尚无记录”。登记、受理、委派开始和最近事件都不是执行开始。

`TaskStore.get` 在显式读事务内取得任务和事件；`list_tasks` 沿用既有读事务，对本页批量读取最新事件（按最大 seq，不按可能回拨的时钟）以及 `role_started`。角色阻塞判断仍复用最新事件。没有新表、索引、迁移、写操作或依赖。开始时间优先用该事件的 `occurred_at`，旧库没有该列时才用这条事件自己的 `created_at`。不返回事件正文、路径或凭证。

两页面复用 `task-activity.js`。响应里没有 `startedAt` 这个键时不新增“开始时间”行，避免旧进程多出一行。已有该键但时间为空或非法，显示“尚无记录”，不从 `agent-line-<taskId>`、登记时间或最近事件猜测。无自动轮询或动作。

开始时间仍只认已保存的 `role_started`。等待原因只解释已有载荷。授权列表显示已保存的业务目标；未授权首页仍只显示任务号。两边列表在响应已有 `workflow.revision` 时显示固定流程版本。授权列表在响应已有 `roleAgentId` 时显示负责人 Agent，不从绑定名称补造。运行详情的原生摘要现在用已返回状态回答整体流程是否暂停；Codex 活动仍是未知，不从暂停推断。运行图成功后显示已核对的项目和固定流程版本，任务参数需另点读取本地根输入。 运行图节点在提交未知、申请取消或已有启动阻塞时显示同一套阻塞原因；没有字段的已登记任务不编造。原版中文覆盖仍未完成，PRD-13.7 仍 unverified。
