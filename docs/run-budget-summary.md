# 运行额度摘要

运行管理中显式查询原运行后，结果区增加“运行额度”。复用已有私有运行查询，不增加请求、计时器、执行按钮或配置编辑。首页仍直接显示已有任务和服务。

后端附加 `budget`，以原授权绑定的项目/工作流/run限定同一TaskStore读取快照，与原WorkflowRunLedger的不可变runBudget交叉核对。既有节点记录不一致、历史损坏或无法确认时返回unknown，不能计零；已冻结且尚无节点的运行可显示原额度和零提交。没有冻结快照且没有节点时仍为unknown；明确无预算显示not_configured，不回填当前项目默认值。

configured摘要显示节点提交已用/上限、剩余次数、执行阶段时限、截止及本地观察时间。`budgetAllowsSubmission`只表示该时点次数/时限检查结果，不代表权限、审批、维护、资源等全部准入允许，也不说明Codex是否停止。配置耗尽与到期保留原取消/退出核对规则。执行阶段从首次节点submission_intent计时，不含之前的Sim运行或等待；重试/循环共享原额度，取消不退款。

前端核对binding/scope、状态、计数、剩余计算、deadline与观察时间对应的预算判断。非法响应显示待核对，旧后端缺字段不展示。换运行、身份或重新查询清除旧摘要，迟到响应由原查询generation阻止。长标识不引入新卡片，沿用原Mac风格简洁定义列表。

不改变原准入事务、schema、模型/金额预算、费用算法或原生记忆。完整token、调用次数、费用仍为null；子工作流跨run额度尚未交付。只做源码/AST/Luna复核，未运行测试、Node、HTTP、浏览器、模型、lint、构建，不能提升AC66或宣称完整PRD完成。

2026-10-28 的并发领取回归不改变这份摘要。`budgetAllowsSubmission` 仍只表示该时点的次数和时限，多个查询可以同时看到剩余。预留发生在领取事务，不在这次只读快照里。

## 计量延迟超额（2026-10-28）

提交次数超过冻结上限时，`remainingSubmissions` 等于上限减已用，可以为负。运行页把这一差额显示为实际超出次数，并写明不能据此把活动进程标成已停止。未超过上限时，剩余次数仍是上限减已用；恰好用尽或到时的原文案不变。已用超过上限但剩余被夹成 0 时，页面显示无法核对，不当成恰好耗尽。新调用仍按原准入拒绝。token、模型调用次数和费用仍为 null。巡检、取消确认和资源生命周期没有改。适配器未重载，PRD-11.9 仍 unverified。
