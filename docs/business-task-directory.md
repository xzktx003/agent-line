# 从业务目标查看所有节点任务

在运行管理的“业务任务”目录，对某条任务点击“查看节点任务”，页面会转到原任务中心，按该项目和业务任务筛选。它展示此目标在多次显式运行中已经登记的节点，执行、验收和记忆状态仍分别显示；点击节点可查看目标、尝试、负责人及Codex身份。

这个按钮不会选用启动目标、启动流程或查询上游原生执行；它只在用户点击时读取现有受授权任务目录。原执行状态和某次运行筛选会清除，避免误隐藏其他运行。若只需要某次运行，可在原范围区同时填写完整项目、流程和运行标识；点击“查看同次运行的其他节点”则切回整个运行，不保留旧业务任务条件。

手工筛选业务任务必须同时填写项目，ID限128位ASCII字母、数字、下划线或连字符。清范围、退出、范围编辑导致旧页失效等行为包含新字段。客户端核对完整筛选回显、每条记录的项目及固定业务任务身份；旧后台忽略参数时会拒绝把未筛选结果当作成功，不自动扩大查询范围。

## 存储与权限

原受授权GET /extension/v1/node-tasks新增可选workItemId；未请求此参数时，filters仍为原projectId/workflowId/runId三字段。提供参数时回显同一workItemId，TaskStore在原查询/游标同一读事务内匹配顶层冻结payload.workItem.workItemId及workItem.projectId，项目还须属于凭证scope。不会用任意input.workItem文字匹配，不以全局同名任务ID跨项目混合。

status可变，不参与身份游标归属检查；业务任务、项目及可选运行范围参与该检查。SQL值参数化，无数据库迁移、索引修改、后台聚合、全量原生查询或新服务。匿名overview不开放此筛选，历史无关联任务保持原列表可见。

目录是已有节点记录的投影：空目录不能证明没有在途提交，节点执行成功不能代替业务验收，分页不能当作业务任务全部完成或预算总计。完整Mission结果/预算/里程碑聚合仍未完成，不新增第二套执行状态。

仅两Python AST及Luna前后端源码复核，无测试、Node、浏览器、HTTP、模型/探针、lint或构建。源码与部署证据不代表实际新关联链路或全部PRD通过。
