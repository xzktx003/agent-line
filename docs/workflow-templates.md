# 使用内置流程模板

中文流程搭建页的项目目录内提供“从模板创建草稿”。先连接项目并读取已配置的角色，选择模板、名称及对应角色，然后创建。创建使用原有接口建立独立空草稿，确认身份和空图后载入模板；必须点击原“保存草稿”才持久保存。发布仍使用原发布按钮及其能力检查，创建和保存不会启动任务。

当前源码提供 20 个模板，每项都有中文适用说明、输入契约、输出契约和完成定义。目录盘点来自源码静态读取，不代表新增模板已经编译或实际运行。

模板的阶段、人工确认位置、角色组合和业务契约随场景不同；场景契约会进入各执行阶段指令。依赖升级、接口契约变更、迁移脚本和重构等流程在写入前设人工确认；故障诊断、安全审查、项目梳理等模板用于只读分析。迁移脚本模板只编写和审查脚本，不应用迁移；发布前核对不执行发布。

不同角色槽位要求不同的正式 Agent，绑定不同但实际Agent相同也不能通过。同一槽位可在多个阶段复用，不按节点创建新角色。列表不足时需先在部署中配置角色；页面不创建 Agent，不按相似名称替代角色。全新安装可显式配置原生三角色团队，见 [单项目准备](single-project-setup.md)。已有主实例不会自动被改成三角色团队。

模板只保存可移植的流程结构和中文指令，没有项目路径、正式角色ID、凭证、历史结果或发布身份。每个草稿生成独立的节点、连线和条件标识。模板映射使用当前项目的正式绑定；后端原有编译器及发布校验仍决定其有效性。

Agent 节点使用 `native-role`，保留 QwenPaw 官方 Agent、会话和 ReMe。不会复制历史记忆或替用户批准记忆写回；默认不强制每节点提交记忆。规划和审查指令要求只读核查，真正的执行权限由部署的原生角色与执行桥决定，模板正文不能提供权限保证。独立测试通过也不等于审查意见自动通过，最后的人工节点需明确决定。

创建回执未知时只查询原操作，保留本页相同模板快照，不重复创建、不自动保存。目标已有内容或身份不符时拒绝覆盖。切换项目、退出会清除名称、映射及未保存内容，刷新后只读取 Sim 中已保存的草稿。创建前丢弃原流程未保存编辑必须按现有界面明确确认。

六项定向测试通过原JavaScript构造及真实Python编译器/读回器核对两种图、权限与人工分支、有限循环和独立命名。六个真实浏览器场景使用明确拦截的API：桌面1440px、手机390px、单角色修复、创建回执丢失、原草稿已有未保存编辑时回执丢失、重复正式角色拒绝。正常场景恰一次创建及一次主动保存，回执丢失只查询原操作，重复角色零写入。退出清空、重读及无页面横向溢出已核对。
