# 中文流程搭建浏览器验收

本轮在专用 `var/sim-authoring-http/` 配置下临时监听 loopback 3196 验证，主服务的
配置、准入守卫、角色和记忆均未改动。这是实际 Sim 接口的浏览器验收，主环境尚未
配置 `authoringFile`，不能据此声称已在统一 QwenPaw 入口交付全部编排能力。

## 实际结果

`probes/sim/editor_browser.py` 在浏览器中完成：

- 使用独立编辑身份选择授权项目，新建一个独立流程。
- 添加开始、条件和两个结束节点，通过表单修改位置和中文 JSON 输出，配置三条连线
  及明确的否则分支。
- 保存并读回，发布并由后端核对确切版本图。
- 重新进入页面后加载同一流程，节点与图保持可用。
- 将一次真实成功保存的 HTTP 回执故意丢弃：页面禁止再次保存，查询同一操作后恢复
  正确状态，整个故障阶段仅有一次保存 POST。
- 凭证仅保留页面内存，浏览器 storage 为零；退出清空凭证和草稿。桌面、手机均无
  页面级横向溢出，画布在容器内部滚动；无 pageerror。

真实 UI 流程 ID：`07277a9d-ee09-48f6-a344-9d1ad6161433` 以实际私有
`browser/state.json` 为准；此 ID 不作为重新创建或接管其他流程的依据。

报告位于 `var/sim-authoring-http/browser/report.json`，原请求回执与未知回执在同目录
`state.json`。该浏览器写入探针检测到已有 state 即拒绝再次执行，避免重复创建；
后续核对使用只读确认脚本。

## 修正与最终确认

发现并修正了文档 ID 含连字符不符合编译器、节点默认重名、手机端选中配置表单后
网格被内容撑宽，以及明确未准入的请求仍使页面保持未知的问题。保留真正的传输
或存储不确定状态，不能因一次 503 就推断可以重试。

`probes/sim/editor_confirmation.py` 对同一流程进行一次有针对性的确认：

- 1440×1000 与 390×844 下，选中节点配置后仍无页面溢出；键盘可选节点。
- 只对无任务的专用探针库进入维护，真实保存请求返回 503 和
  `X-Agent-Line-Admission: closed`；没有新操作登记、没有 Sim 修改。页面显示未提交，
  用户可以修正后主动操作，不会进入无记录可查的永久等待。
- 检查后释放本探针自己的维护凭据；主库守卫未变。已有运行工作台新增导航也保持
  手机端无页面溢出。

最终报告 `confirmation.json` 为 passed，新操作登记 0，浏览器错误 0。桌面和手机
截图均在上述私有目录，视觉结论在 `.omx/state/workflow-editor/ralph-progress.json`。
Impeccable 检测器因解析依赖缺失降级为正则检查；出现辅助色、字号和圆角文档建议，
已说明其设计用途，未将降级检查当作完整视觉验收。
