# 从运行详情追踪节点任务

状态：2026-10-23源码接通，适配后端已按原配置重载，尚未做功能验收。未新增或执行测试。

任务中心增加三个可选精确筛选项：项目标识、工作流标识、运行标识。可只筛项目；按运行筛选时必须三项齐全。结合原执行状态和每页条数使用，仍按已有任务ID游标翻页，不根据标题猜测业务归属。

成功查询工作流运行后，若当前授权绑定目录提供确切projectId/workflowId，可手动选择“查看本次运行的节点任务”。该入口填入原查询运行的身份，筛选其在适配任务库中已经登记的节点任务；不自动查询恢复子运行，不发起执行、重试、取消或审批。

列表默认突出角色、项目、节点与执行/验证/记忆分离状态，完整workflow元数据中的流程、运行、任务、激活和尝试标识可按需展开。选择任务仍打开原有详情/产物/事件/记忆入口。目录不是整个业务WorkItem模型，也不是所有原生运行或尚未登记节点的完整画布。

## 接口约定

沿用GET /extension/v1/node-tasks，增加projectId、workflowId、runId三个可选查询参数，每项1–256字符且不能含首尾空白。workflowId/runId必须同时出现并提供projectId；项目标识必须在当前Bearer凭证的授权范围内。保留after、limit与status参数，不改变凭证、项目scope或任务读取权限。

响应增加filters对象，三个键始终存在，未指定值为null。前端在应用筛选时核对精确回显与整页各任务身份；旧后端忽略新参数但没有filters回显时，不展示其宽泛结果为已筛选目录。不带新参数的旧接口体验保持。

TaskStore在原授权JSON字段SQL上追加绑定参数，不拼接用户值。带筛选的游标必须属于相同授权项目/流程/运行范围，越界与不存在统一404；执行状态会变化，所以原游标任务离开所选状态不会单独导致失效。身份、游标与页面读取在同一只读事务内完成，limit+1决定下一页；无新增数据库、迁移、索引或存储副本。

## 页面边界

修改筛选条件即清除旧页和游标、隔离迟到响应，提示显式应用后读取；退出清空筛选与结果。范围表单置于明确命名的折叠区，从运行详情进入时自动展开并清除旧状态筛选。分页必须有明确回执，非空游标匹配末项且不同于本次after，否则整页拒绝显示。运行入口仅使用当前绑定目录的身份，不把原生子run输出反推为原任务范围。没有浏览器存储或凭证URL，没有自动轮询或新模型调用。所有结果仍经过原授权接口，选择条件本身不授予权限。
