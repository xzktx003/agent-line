# 任务等待与阻塞原因（2026-10-23）

补PRD13.4/13.7。现有授权任务页已有executionQueue和submissionBlock，而无需连接的首页仅有状态；本轮把原本只读队列诊断接入首页，统一两任务列表和详情的中文关注提示。

TaskStore.list_tasks增加可选include_queue（默认false），只有服务端目录调用显式开启；同一已有读事务内、仅registered任务调用原_queue_reason，不改claim、调度、重试、持久状态或原生记忆。接口只投影队列策略/等待状态/固定reason及原角色阻塞代码，无占用方ID/数量/路径。详情仍保留原授权与现有诊断入口。

前端公共task-activity.js按已提供的领域状态给具体提示，未知或缺字段明确待核对；区分已登记、受理未知、已绑定而未得终态、取消请求、资源退出、独立验收、记忆审核/回写。不能从普通accepted推断正在运行，不能凭pending猜测已有验收进程；不从事件历史猜测当前审批，不开放匿名操作。原三类状态和资源事实保持独立。
