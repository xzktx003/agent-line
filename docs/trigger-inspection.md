# 已配置自动入口与原事件核对

运行管理页默认折叠的“已配置自动入口”读取当前操作身份可见的既有配置，支持分页、选择入口、按原事件标识核对本地提交记录。首页任务与服务仍直接查看，无连接表单。本面板不创建入口、不投递事件、不启动工作流；不包含 Jira 集成或新增调度器。

原授权 `GET /extension/v1/triggers` 仅返回启用项目的固定入口标识、项目、绑定及类型；已配置不代表外部调度器运行中。原授权 `POST /extension/v1/triggers/{triggerId}/lookup` 仅读取提交日志，事件标识放请求正文，避免进入 URL。Webhook 标识保持原始字符，包括首尾空格；计划事件要求规范 UTC 分钟 `YYYY-MM-DDTHH:mm:00Z`，不生成当前时间替代原事件身份。

核对共享原触发命名空间和运行 UUID 算法，在同一 SQLite 读事务中检查冻结定义、发布版本及根提交记录。未找到定义、未找到根记录、已有提交记录分别显示；缺少记录不能证明未执行，始终返回 `safeToResubmit=false`。只有已有定义可计算的运行身份才提供回填运行表单按钮，用户随后显式查询。无原生请求，不返回事件输入或原回执正文，不改变提交语义。

目录及核对响应禁止缓存。换身份、退出、换入口、翻页、修改标识使旧结果失效。初始目录 404 显示未配置；后续分页 404 显示查询失败，不能据此断定服务未配置。兼容保护仍按原策略阻止 POST，故只读核对也可能收到 503，不绕过保护。未配置 `triggerFile` 时路由不存在；本次不修改正式配置。

本轮仅源码阅读、Python AST 与静态复核；没有测试、Node、浏览器、HTTP、模型探针、lint 或构建。入口创建界面、实际外部调度与完整业务验收仍待完成，全部 AC 状态保持。
