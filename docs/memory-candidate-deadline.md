# 记忆候选写入期限

在记忆审核正文下展开“候选写入期限”，选择本机时区的未来时间，点击“应用到正文”。正文首行记录 `候选写入截止（UTC）：YYYY-MM-DDTHH:MM:SSZ`，并取消此前同意勾选。留空后应用可移除尚未审核正文的期限；已审核正文和正文哈希保持不可修改。此功能可选，没有期限的旧正文保持原行为。

这是**候选新写入期限**。到期后禁止新审核登记、首次写入意向和明确失败后的新重试意向。写入意向在截止前已登记的任务可能在截止后取得结果；未知回执只核对原身份，不借到期重发。已有历史记录、intent/pending核对、删除和墓碑仍可查询处理。

期限不控制QwenPaw原生召回。已经写入的内容到期后仍可能被原生记忆检索，不会自动删除、清索引或阻断角色。PRD要求的完整记忆失效/原生召回过滤和检索效果评估仍未完成，本功能不能代替它们。

服务端使用原审核正文，无新数据库、字段迁移、后台计时器或记忆引擎。首行标记与正文一起哈希冻结：只允许一个标记且在首行，UTC时间严格到秒、实际日期有效，并且标记之后必须有正文。正文存在标记但格式错误、日期无效或重复时拒绝新写入。到期判断以服务端当前时间为准，等于截止时间即过期；不解释其他自然语言失效条件。

新审核在持久审核登记前检查；`MemoryCommitStore.claim` 仅approved→intent时再检查；`retry_claim` 在新retry intent前检查。既有intent/pending分支不检查期限，以保留原提交收敛能力；committed不因日期经过而改成失败。重放已存在审核保留原审核快照与哈希约束。

`GET /extension/v1/memories/bindings` 对每个可访问绑定声明 `candidateWriteDeadline: utc-header-v1`。详情增加 `candidateDeadline`，包含 `state`（not_set/active/expired/invalid/unavailable）和可核对的 `expiresAt`；这是正文期限观察，与原写回status独立，删除后正文不可用时为unavailable。没有带出记忆正文以外的新来源或隐私字段。

前端本地检查只用于及时提示，服务端仍为最终边界。旧服务未声明保护时，不允许设置或提交带期限的候选。单项提交、加入批量、批量真正发起一项之前分别核对；排队中经过截止时间的项不能新增发送。切换来源清未应用的时间。因正文中已冻结期限而拒绝的原失败记录不能通过修改同一审核绕过，需要保留历史并按原来源与更正流程人工处理。

仅源码阅读、标准库AST和指定Luna静态复核，无测试、Node、浏览器、HTTP、模型、lint/typecheck/build。部署信息见对应维护记录；实际新审核/过期边界/重试/批量/原生写入尚未运行验收。完整PRD及AC计数不因该保护增加而提升。
