# 任务等待与关注事项

首页“任务与服务”、运行管理任务列表和任务详情在已有分离状态之外显示“需要关注”。按接口已提供字段解释，只在有待处理或待核对事项时出现，不增加操作、自动轮询或重新执行。

有等待原因时，首页、运行管理列表和任务详情先显示“等待原因”。与“需要关注”文字相同时不再重复。已绑定身份、验收失败和记忆失败不是等待原因。没有队列载荷的已登记任务仍只显示“需要关注”。原生全部等待原因和真实交互验收仍待完成，PRD-13.7 不改为 passed。

已登记任务沿用原串行队列诊断：执行准入关闭、角色/工作区占用、前序等待、节点提交次数上限、整次运行提交额度/时限及原因未知。角色版本与执行准入证据阻塞单独解释。只有固定原因代码，没有占用者ID、任务数、工作区路径、输入输出或凭证。该诊断不代表已经通过所有原生准入检查。

提交/受理未知提示查询原任务并避免重投；已绑定原生身份只表示还没拿到终态，不能称当前正在运行。取消申请等待原执行与资源退出确认。执行成功后，资源未退出、结构校验错误（仅已有授权详情提供时）、独立验收待结论/失败/取消、记忆待审核/回写失败/删除未完成分别提示。首项用于快速定位，原执行/验收/记忆状态和原始详情继续保留。既有全量审批/等待输入信息缺失时不猜测，不从历史事件重建当前审批。

TaskStore.list_tasks增加服务端可选include_queue，默认false；当前两目录显式true，只对registered任务在同一读事务内复用_queue_reason。后台调度器与claim规则不变。通用取消请求、独立验收取消请求各按自己的事件集合与最后事件同批聚合，形成任务快照；通用取消仍用于既有保守操作保护，验收取消展示只认verification_cancel_requested，避免把历史执行取消误称停止验收。需独立测试的私有目录投影不用再次get刷新整行、丢弃队列快照；单任务get沿用同一取消事件集合，语义不变。缺事件不创造取消或开始记录。

无需连接的首页只追加固定队列/角色阻塞元数据及既有测试验收的取消请求布尔摘要，仍不开放详情、启动、取消、审批等权限。公共前端文件统一文案，旧接口缺字段或未知代码说明待核对，不补造原因。

仅源码、Python AST及独立Luna静态审阅，没有新增/运行测试、Node、浏览器、HTTP、业务模型、探针或lint/typecheck。原生全部等待原因、实时画布、完整WorkItem及真实交互验收继续待完成，不提高PRD AC状态。
