# QwenPaw 隔离提交升级演练

本演练补充候选源码准备与只读兼容报告，实际启动两个固定提交，验证角色、官方
记忆文件、认证与插件入口在提交切换及备份恢复后仍可读取。它不切换正式服务，
不修改正式虚拟环境或 upstream，不把同发布版本内的提交切换称作跨发布版本升级。

## 命令与作用范围

先用 prepare_upgrade_candidate.py 分别准备旧、新提交。当前固定组合：

- 旧：28f2b9f624d4917268f964cffc8c3cba519f8b87
- 新：502b59d88464d5c9e8be4a507347282d6a54e0be
- 两者均为 2.3.0b1，依赖声明相同；功能变更包括 ACP 长工具调用结果保留。

运行：

```bash
.venv/bin/python probes/upgrade/qwenpaw_persistence.py --attempt commit-persistence-1
```

attempt 必须是尚不存在的目录名；失败现场保留，不在原目录自动重试或覆盖。
数据在 var/upgrade-runtime/<attempt>；日志和秘密文件仅所有者可读。该探针没有
模型调用、外部通知或正式项目写入。

Runtime 经正式 python -m qwenpaw 入口启动，PYTHONPATH 指向候选 src，禁用
pycache，使用独立工作目录、密钥目录与本地随机账号，并禁用 keyring。
复用已有虚拟环境的依赖；不会 pip install，也不宣称已重建完整独立依赖环境。
启动前核对候选 pyproject 在当前环境生效的直接依赖，缺失或版本不符则拒绝；
记录依赖版本指纹。这不是 extras/传递依赖重新解析或完整环境重建。
每个阶段核对 qwenpaw 实际导入路径确实来自目标提交，而非当前安装包。

## 真实步骤

1. 旧提交初始化全新测试实例，通过认证 API 创建固定角色并写入测试记忆。
2. 停止且确认该实例退出，离线备份 data 与 secrets。
3. 同一路径启动新提交；核对原角色 ID、名称、后端及记忆内容，写入升级后测试内容。
4. 停新提交，整体保留升级后目录；将备份恢复到原测试路径，保留配置中合法的绝对路径。
5. 重新启动旧提交；确认原角色和升级前记忆恢复，升级后新内容不混入旧备份。
6. 停止测试实例并保留报告、日志、备份和升级后数据。正式服务全程不参与。

仅停止与记录 PID、启动时刻、命令和环境均匹配的测试进程。启动失败不结束正式
QwenPaw；无法证明所有权时拒绝发送信号。

## 验收边界

该演练是官方记忆读写持久性验证，不是原生模型 memory_search 召回、Codex 实际
委派、在途任务恢复或 Sim 数据迁移验证。跨发布版本、正式升级切换、完整九项
兼容探针、不可逆迁移及持续运行仍需独立证据。不得用本报告直接解除生产准入。
