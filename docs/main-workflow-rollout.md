## 接入方案

- 原TaskStore和SimJournal保持原路径，不导入候选任务、证明或其他日志；旧两项任务
  的原行内容保留。原审批、记忆提交及审核数据库继续使用。
- 新项目绑定既有 `agent-line-native-loop-parent`。现有执行器只连接这一项已核对的
  角色与工作区；旧绑定继续支持历史读取和原记忆功能。没有实际gateway的新任务
  返回中文503，不能因为全局能力confirmed而留下永远不执行的登记。
- task-flow复用原审批run账本，只新增暂停绑定账本；编辑凭证与服务/审批凭证独立。
  配置全部使用绝对路径，复制回主配置位置不会改变路径含义。
- 角色仍使用原生记忆。节点默认不要求额外人工记忆提交；这与关闭原生记忆无关。
  当前受信策略为隔离工作区的接入验证代码和三项独立测试，不作为任意业务任务
  已验收的声明。通用项目策略和完整PRD继续追踪。

## 切换与回退约束

1. 核实3193监听进程的PID、start ticks、用户、解释器、工作目录和配置引用。
2. 只停止该适配服务，确认监听和worker退出，备份原配置及涉及的现有SQLite库。
   原数据库必须静止、无排队任务和工作区租约；不停止QwenPaw、Sim或网关。
3. 核对普通维护锁类型后，使用原owner正常解除自身维护锁；不能清除恢复隔离、
   原生删除墓碑或其他工作区的未知租约。
4. 在原TaskStore执行一次明确、唯一的运维验收任务。先持久intent，复用现有
   Dispatcher、原角色/Codex和独立AutomaticVerifier。节点验收不解释业务流程图，
   不通过public配置布尔值开放执行。未知回执只观察原身份。
5. 原生父任务finished、原始执行/测试/退出证据核对成功后，从同一原库构造readiness。
   正式load_app验证新配置、原历史及准入，再原子替换主配置，在原3193端口启动。
6. 新编辑器从真正的新建操作开始，不收编候选模板或未知创建请求。

新任务一旦可能受理，回退不能恢复任务数据库或丢弃新gateway/账本：先重新进入
维护，继续核对原身份直到确认退出。没有活动新执行时可回退配置，但必须保留
新增任务和全部原始证据；数据库回退不能撤销外部模型或项目文件变化。
