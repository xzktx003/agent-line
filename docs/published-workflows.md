# 从发布流程到运行入口

流程发布成功后返回 `bindingId`、`revision`、`deploymentVersionId` 和 `graphSha256`。
配置同一 Sim 连接、同一出站日志的 authoring 与 workflows 后，现有
`GET /extension/v1/workflows` 自动列出这些发布绑定，原运行接口直接接受该标识。
不需要手工把每次创建的原生流程 ID 写进服务配置，也没有增加目录数据库或服务。

目录只读取当前已配置、启用项目的出站日志：必须同时有 accepted 的创建归属记录和
accepted / published 的发布回执。原生 Sim 工作区可见性不等于项目归属。
缺少新绑定字段的旧回执保持历史记录，不自动变成可执行入口；用户需明确重新发布。
原静态绑定保持兼容。目录列表只返回项目、绑定和版本，不返回机器任务策略或秘密。

新运行先核实原生版本的活动状态、部署 ID、数字版本及无损编译后的图指纹。
项目、绑定、图指纹、发布版本和机器任务策略在 execute 前写入原 SimJournal，
机器任务仍在原 WorkflowRunLedger 冻结策略，由现有后台发现/执行/回传线程处理。
目录不推进节点、不写角色或记忆、不自行调度流程。

新发布版本拥有新绑定。目录绑定的运行身份包括安装、项目、流程、触发标识及绑定 ID；
同绑定同触发同输入重复请求只返回原意图，不重新执行。不同版本即使使用相同触发标识
也是用户明确选择的新运行。原静态绑定保持原运行 ID 算法。
旧绑定的新触发在版本不活动时被拒绝，原运行仍可查询、重放提交回执；跨绑定查询拒绝。
维护期间允许读取和重放已存在回执，禁止新意图。超时或进程中断留下的原意图不重发。

编辑器发布回执与重新读取草稿都会展示发布入口。链接仅传非秘密绑定 ID，
运行页只预填、不自动启动，仍需独立的运行凭证。

## 当前版本限制

已补真实“版本1等待 → 发布版本2 → 版本1继续 → 新运行采用版本2”的主服务验证，
含原生角色/Codex、独立三项测试、实际图及两个不同End输出，见
[运行中改版验证](workflow-republication.md)。原始子日志探针错误与初版2的180秒
超时均保留，修正既有预算后使用新的独立运行完成版本2正例，不重写旧结果。

Sim 的公开 execute 接口没有指定历史 deployment 的参数。本适配器在提交前检查当前
活动版本，并与自己的发布操作共用锁；独立 Sim 编辑器不参与该锁，仍可能同时发布。
机器任务派发前会再次核对实际运行快照，发现版本不符则不执行 Codex。
因此不能把本实现宣称为任意历史版本固定执行或对外部编辑器的原子发布锁；完整
AC-21 的运行中改版场景与此额外的外部编辑竞态须分别记录，不能互相替代。

`tests/test_published_workflows.py` 使用真实任务库、出站日志和 HTTP 路由验证创建、保存、
发布、列表、启动、查询、机器策略冻结、权限、维护、版本变化与未知提交防重。
这些模拟上游测试不替代真实 Codex、浏览器或版本切换验收。
