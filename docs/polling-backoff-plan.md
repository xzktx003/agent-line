# 执行观察有界退避计划

在现有DispatchLoop内调整同一任务的观察频率，不增加调度器、持久任务或模型调用。只缓存任务身份及本地状态版本的有界内存计时；重启清空后继续观察原任务，不重提执行。

区分来自传输层的429限流、5xx/连接不可用、其他未知，以及已观察但本地快照持续不变。未知指数退避最多30秒，限流按有界Retry-After及最低5秒处理；本地无变化持续30秒后最多5秒观察一次，但不宣称原生停滞。状态版本变化重置退避。只影响观察，不自动重试提交或记忆。

每轮先检查运行stop及最新任务状态。取消、已到节点/运行时限必须绕过退避，仍按原流程观察后请求取消；已释放的成功任务独立验收继续按原节奏，不被查询退避跳过。角色/工作区租约、readiness、预算及原任务身份保持。记录仅传输提示，不作为终态或释放证明。

现有worker健康可显示最近一页已查询/暂缓数量，明确这是本地节奏而非远端在线或停滞判断。只源码/AST/Luna复核，无测试、Node、浏览器、HTTP、模型、构建；部署不发查询探针、不创建任务。
