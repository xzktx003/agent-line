# 本地执行巡检状态

现有认证接口 `GET /extension/v1/health` 增加 `executionObserver`。它只读取原
`ExecutionWorker` 的内存状态，不触发原生查询、模型任务或数据库事件写入。
2026-10-22已按原配置重载主适配服务，本增量在主工作台生效；主界面真实局域网
1440px/390px核对通过。受控执行仍unknown/readyfalse，原生QwenPaw未重启。

| status | 含义 |
| --- | --- |
| not_configured | 当前应用未配置执行巡检线程 |
| not_started | 已配置，但线程尚未启动 |
| starting | 线程存活，首轮扫描尚未完成 |
| healthy | 最近扫描完成，未报告错误；空闲扫描也可正常 |
| degraded | 最近扫描报告错误，仍保留原执行身份与状态 |
| delayed | 线程存活，但在观察窗口内没有完成一次扫描 |
| stopped | 已创建的巡检线程当前不再存活 |

`lastScanCompletedAt` 是最近扫描完成的 Unix 秒数，未完成时为 null；
`secondsSinceCompletedScanOrStart` 使用单调时钟计算，尚未启动时为 null。
观察窗口是60秒和三倍轮询间隔的较大值。长请求也可能产生 delayed，这不证明
底层任务没有进展、已经离线或已经停止；没有据此取消、释放资源或重提任务。

这些字段不替代 `controlledExecution`、`readyForExecution`、任务观察状态及原生
资源退出证明。`healthy` 仅说明本地扫描完成，不能解释成远端 Agent 在线或所有任务
成功；最近错误后的新扫描完成时可恢复 healthy。这里不公开任务编号、错误正文、
凭证、工作区或供应商信息，扫描状态只保存在原线程内，重启后重新观察。

实现为 `agent_line/worker.py` 和现有 `agent_line/service.py` 健康响应，
回归在 `tests/test_worker_health.py`。26项相关测试通过：真实空闲扫描及认证查询不
调用 gateway、不改变数据库全部表；阻塞扫描超过窗口、恢复和停止；扫描异常后的
继续运行、恢复与错误脱敏。故障和时间场景属于明确注入，不是实际供应商断连证明。

实际 Uvicorn/HTTP 隔离核对为匿名401、认证三次200/healthy、数据库内容保持，
模型及上游请求0。测试结束后服务与巡检线程均已停止。私有证据在
`var/worker-health-20261022/http-report.json`。

AC-69仍未通过：任务级无进展判断、实际执行断连/恢复、限流退避及完整健康界面
尚待实现和验收。这次只补本地巡检事实，不新增巡检服务或第二套调度器。
