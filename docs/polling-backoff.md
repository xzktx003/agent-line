# 执行任务查询退避

在原 ExecutionWorker / DispatchLoop 内对同一任务的观察查询安排有界等待，不新增服务、调度器、数据库表、模型调用或依赖。提交、业务重试、记忆写回不进入该策略。Sim 发现等其他循环仍沿用原间隔。

## 节奏与边界

- 查询未知：连续结果采用 2、4、8、16、30 秒等待，最多30秒。不沿用离线阶梯。
- 传输不可用（离线）：连续结果采用 3、6、12、24、30 秒。不沿用未知阶梯。
- HTTP 429：仅传输层提供的数字 Retry-After 有效，等待限定5至30秒；HTTP日期、非法值或缺省回退5秒。不沿用离线或未知阶梯。
- HTTP 401/403：30秒后再观察，不修改凭证或自动切换身份。
- 已观察且本地状态快照持续30秒不变：等待逐步为2、4、5秒。快照不变不证明原生 Agent 停滞或失败；默认正常观察等待1秒，实际还受原扫描周期和分页影响。无进展不沿用离线或限流等待。
- 同一种情况连续出现才进入下一档。换成另一种情况，或本地五项指纹变化，就从该情况自己的第一档重新开始。
- 本地执行状态、任务版本、资源退出、验收或记忆状态变化，立即重置原等待；取消请求、运行停止及已到时限绕过等待，继续原观察与取消处理。定时器不构成终态或资源释放证据。
- 成功且资源已退出的独立验收仍按原路径运行。已登记任务按原准入逻辑提交，退避不会重复提交。

内存仅缓存最多2048个任务标识及五项本地状态指纹，不缓存输入、原生正文或凭证；未触及条目超过300秒移除，容量满移除最早使用条目。计数和等待均有界，使用单调时钟；进程重启清空计时，随后仍观察原任务身份，不重建执行。响应结构校验失败保留原错误及unknown记录，同时安排后续观察退避。

上游成功响应不能自行指定传输提示，观察网关会移除成功正文中的pollHint/pollAfterSeconds，避免模型正文控制查询频率。

## 界面说明

原授权健康接口增加queryCadence，只汇总最近完成扫描页内当前凭证可见项目：尝试查询任务数、等待任务数、最长剩余等待。不是全库统计、HTTP请求总量或原生有效回执数量。无需额外查询，无任务ID或正文；本地线程健康与原生执行/验收/记忆结论仍分开。

## 当前证据

仅源码与标准库AST审查，未执行应用行为、测试、Node、浏览器、HTTP或模型探针。源码和空闲服务重载不能证明运行中断连、限流、取消或超时场景已经通过；验收矩阵不提升。

## 分别退避（2026-10-28）

离线、限流与无进展不再共用一条等待。服务不可用使用 3、6、12、24、30 秒。未知仍是 2、4、8、16、30 秒。限流仍至少 5 秒，并遵守 1 到 30 秒的 Retry-After；重复限流不因为次数自动加长。本地快照持续无进展仍在满 30 秒后按 2、4、5 秒，未满 30 秒仍是 1 秒。同一种情况连续出现才进入下一档。换成另一种情况，或本地五项指纹变化，就从该情况自己的第一档重新开始。这只影响观察查询，不调用模型，不把健康检查变成监控任务，不改变预算准入、未知用量或取消确认。

项目虚拟环境 unittest 17 项通过，覆盖 `tests.test_poll_backoff` 与 `tests.test_dispatch_loop`。没有重载适配器，没有调用现场健康检查。PRD-11.9 仍 unverified。
