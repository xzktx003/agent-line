# 流程暂停、继续与停止

控制接在现有适配服务中，复用 Sim 提交日志、节点任务取消与后台发现器。QwenPaw
继续负责原生角色、会话和记忆；不新增调度器、运行服务、配置文件或数据库格式。

## 用户看到的行为

- **暂停后继任务**：停止该运行的新任务登记、排队任务出队、新结果回传和新人工决定。
  新暂停必须写明活动 Codex 是继续还是中断。继续不申请取消，已获准的在途请求先收尾，结果留存到显式继续。
  中断只对当前 accepted、submitting、uncertain 的本运行任务申请取消；registered 保持排队。
  这不调用 Sim 的取消日志，也不把资源标成已释放。未确认前不能当成已停止。
  旧记录没有该选择时显示未记录，按原载荷重放不会补成继续或中断。
- **继续流程**：核对原生暂停、准确发布版本、先前恢复回执、任务状态和已记下的审批。
  未知提交、未确认取消、错误版本、不可观察的活动任务，或同一请求仍是 waiting 且没有决定，
  均拒绝继续。排队和已结束任务都要核对。expired、unbound、decision_recorded 不阻止。
  没有 requestId 的旧 waiting 和损坏记录失败关闭。这里只读已保存事件，不查询原生审批。
  没有审批记录时仍按原来的核对继续。继续开放原身份的准入，不新建 run 或重复执行已完成的 Codex。
- **申请停止流程**：先持久阻止后继准入，再请求取消本项目、本工作流、本 root run
  的任务及 Sim 运行。排队任务可直接取消；活动任务沿原受控取消接口继续核对。
  停止后的原运行不可重新开放，结束不删除 Agent、记忆或项目文件。

关闭浏览器不取消后台任务，页面关闭时也不再发送停止、取消或新的查询。原运行标识只写在地址栏的 `binding` 和 `run` 上，不进入本地存储。重新打开只预填该运行；授权后按这个标识重新查询，不启动新运行。页面若从往返缓存恢复，同样不补发停止。

停止适配服务不向进程组发信号。Codex 执行客户端在独立会话中启动，退出时只向启动时刻仍匹配的那个 PID 发信号。时刻变化或无法证明时不发信号，避免误杀其他 Codex。容器仍只按已有所有权检查清理。结束时只移除已证明的 64 位十六进制容器，不删除正式 Agent、长期记忆、项目文件或需审阅工作树。身份不合格、容器 ID 含工作区路径，或这些路径在删除后消失，就拒绝。

Sim public v2 没有任意运行冻结接口。“暂停”指停止后继准入、在受控等待点停留，
不能承诺把正在计算的 Sim 条件或已发出的网络请求即时冻结。原生执行状态继续照实
显示；本地 `stop_requested`、Sim `cancelled` 和 Codex 资源退出是独立事实。

## 接口与持久身份

已接入冻结机器/人工等待策略的运行支持：

```text
POST /extension/v1/workflows/{binding}/runs/{rootRun}/control
{ "operationId": "本次唯一标识", "action": "pause|continue|stop", "expectedVersion": 0 }
暂停另须 "activeExecution": "continue|interrupt"。继续和停止不能带这个字段。
```

接口沿用项目服务凭证与运行归属检查。返回 `operation`（原命令回执）和 `control`
（当前控制状态、版本、最近操作 ID、任务/资源计数），停止时另有 `cancelSubmission`。
原运行 GET 同时返回 `control`；未接入受控等待的运行显示 `supported:false`。
原来的 execution/resumption 及节点执行、独立验收、记忆三个状态维度不改写。

每个命令冻结项目、动作、预期版本。相同 operationId/载荷重放返回原回执，不再
改变状态；旧版本或改变载荷返回 409。继续前的核对在该运行排他锁内进行，拒绝时
不落新命令。浏览器只发送一次，未知回执保留原标识并查询；更晚的不同操作不能被
当成原请求未生效，当前界面会保持待核对，不自动生成新标识重发。

本地命令以 `run-control-{operationId}` 记录在已有 SimJournal operations 表；
schema 仍为 1。原生取消单独使用固定 `run-cancel` 身份；两者不混入 resume 子运行
历史。记录读取校验完整版本链；日志文件丢失、损坏和非私有文件不能默认为开放准入。

每个运行有独立的私有文件锁。任务登记、claim 到已获准提交、新结果 resume、
人工决定到 resume 持共享锁；控制命令持排他锁。因此命令返回后不会再有新的受控
准入，而已获准的请求可以先完成。锁只服务现有调用，不解释流程边或调度后继。

## 取消回执和恢复

官方取消为 best effort。回执只说明请求受理，`verifiedStopped` 始终为 false；
已结束运行的 no-op 也不会伪装取消成功。实际退出依赖原生任务终态和已有受控容器
owner、完整 ID、非运行状态、PID=0 等资源证据；请求超时不释放写租约。

停止命令已提交、取消意向尚未写入时崩溃，现有机器或人工发现线程会重新扫描原
运行并补上首次取消意向。若已有 `intent/uncertain`，只返回原记录，不重发、不换 ID。
节点执行循环发现停止后，同一次扫描会把该运行全部仍是 registered 的任务移出队列并记为 canceled，记录保留，不调用原生取消。accepted、submitting、uncertain 仍只进入 cancel_requested，资源未释放前不是已停止；当前页之外的活动任务也不会被提前标成已退出。活动任务的原生取消回执在没有匹配的容器退出证明前保持 cancel_requested，resourcesReleased 为 false。父任务停止确认和委派撤销都不能代替该证明。没有撤销时，即使原生报告退出也不释放；撤销成功后的后续观察仍可报告同一原生退出事实，但证明落地前不是已停止。维护门禁阻止新的 Sim 取消提交时，
本地停止和任务取消请求仍保留，界面不能将其视为原生已停止。
