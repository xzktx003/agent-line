# Kanban原生会话结果摘要联动

本机源码补充证据：GET /api/agent-sessions 只调用registry.list，后者仅读已有会话Map、排序副本并生成目录时间；不走task-summary或tmux详情更新路径。因此可复用目录GET做有界只读投影，不修改/启动Kanban仓库，不注册会话、不发送终端输入。

现有project可选kanbanReadOnly配置只接受管理员明确登记的数字loopback HTTP源及显式端口，禁止用户请求指定地址、重定向、环境代理、借用运行Bearer或其他凭证。没有配置/原Codex会话ID时不请求。严格流式体积/时间/JSON边界，只匹配原任务Codex thread、已授权工作区和明确本地Codex来源，重复匹配视为不明确。

仅返回匹配会话的连接/交互状态和有界已有Agent摘要，排除其他会话以及目录的终端正文、SSH、命令、工作目录和源地址结构字段。授权摘要本身是自由文本，可能提及任务相关文件或命令，不能声称全面语义脱敏；当前运行凭证在截断前移除。目录生成时间与旧摘要时间分开，摘要不保证属于本任务turn，不能改本项目执行/验收/记忆状态。原运行Bearer、expectedVersion、读取后执行身份重查。

任务详情默认折叠、显式读取，不新增服务连接表单或自动轮询。原正式配置保持，默认未登记源；不扫描/猜端口或发HTTP验证。源与UI/路由分别实现，指定Luna静态审阅，源码/AST和空闲维护重载，不运行测试/Node/HTTP/浏览器/模型/lint/build，不计完整P2验收通过。
