# 记忆删除界面接线计划

目标：复用已实现的受控删除与状态核对接口，在现有记忆页提供独立删除确认及查询入口。不新增删除引擎、调度器或内容库，不修改 QwenPaw，不实际删除正式记忆。

1. 绑定目录增加当前身份是否可发起删除及该角色是否配置删除的布尔投影；权限仍由现有后端 `delete_memory` 校验，缺字段按不可用处理。
2. 仅已核对、已提交、原摘要有效且无删除记录时允许删除；显示项目/角色/来源任务、原正文摘要和真实索引能力限制。需要独立勾选确认，不能复用写回审核勾选。
3. 第一次点击固定决定与摘要，只发一次原delete POST。超时、不明回执或身份不符时只查询，不重发；换来源/退出清空敏感草稿和决定，但保留本页面非敏感防重标识。删除请求后清除旧正文和技能候选，不能用旧正文再生成技能。
4. 查询同一deletion GET，显示删除意向/需核对/文件消失/索引消失/角色阻断的分别事实。false不代表文件存在，只有明确双重消失才能显示完成。当前原生索引未确认时角色可能持续阻断，操作前明确说明。
5. 复用中文表单/折叠区/焦点样式，退出与迟到响应隔离沿用现有epoch；不自动批量删除、不启用能力、不修改真实配置。

只源码阅读、Python AST 和独立静态复核，不增加或执行测试、Node、浏览器、模型、探针、真实接口操作或服务重载。AC-12继续in_progress，不能把界面接线当作原生索引治理验收。
